# 评测模块

> 本文档描述评测模块的设计理念和评测指标体系。具体 API 签名和使用方式请参考对应源码文件中的 JSDoc 注释。
>
> 评测是 RAG 系统持续优化的基石。本模块从三个维度对系统进行全面评估：检索质量、生成质量、端到端效果。

---

## 一、检索评测 (Retrieval Evaluation)

检索评测回答一个核心问题：**检索器找到的文档，到底好不好？**

所有检索评测器实现 `RetrievalEvaluator` 接口（定义在 `@rag-sdk/core`）：
```typescript
interface RetrievalEvaluator {
  evaluate(results: SearchResult[], groundTruthIds: string[]): MetricResult
}
```

> 源码详见：`packages/evaluation/src/retrieval/`

### 1.1 Recall@K（召回率）— `RecallEvaluator`

#### 概念说明

Recall@K 衡量的是：在所有相关文档中，检索系统成功找到了多少。它回答的是 **"有没有漏掉"** 这个问题。

#### 计算公式

```
Recall@K = |检索到的相关文档 ∩ 所有相关文档| / |所有相关文档|
```

#### 核心特性

- K 越大，Recall 越高（检索范围越广，越不容易遗漏）
- 当 K = 全部文档数时，Recall = 1.0
- 侧重"找全"，对"找准"不敏感

#### 适用场景

- 法律检索：不能遗漏任何相关判例
- 医疗诊断：需要找到所有相关病例
- 合规审查：必须覆盖所有相关条款

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `k` | `number` | `10` | 取前 K 个结果进行评测 |

#### 使用示例

```typescript
import { RecallEvaluator } from '@rag-sdk/evaluation'

const evaluator = new RecallEvaluator({ k: 5 })
const groundTruth = ['doc1', 'doc3', 'doc7', 'doc9']

const result = evaluator.evaluate(results, groundTruth)
// result.score = 找到的相关数 / 4
```

---

### 1.2 Precision@K（精确率）— `PrecisionEvaluator`

#### 概念说明

Precision@K 衡量的是：检索到的前 K 个结果中，有多少是真正相关的。它回答的是 **"结果干不干净"** 这个问题。

#### 计算公式

```
Precision@K = |Top-K 中相关的文档| / K
```

#### 核心特性

- K 越大，Precision 通常越低（靠后的结果相关性递减）
- 侧重"找准"，对"找全"不敏感
- 分母固定为 K，不受 ground truth 总量影响

#### 适用场景

- 搜索引擎首页：用户只看前几条，要求每条都相关
- 推荐系统：推荐列表中的每个推荐都要"靠谱"

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `k` | `number` | `10` | 取前 K 个结果进行评测 |

#### 使用示例

```typescript
import { PrecisionEvaluator } from '@rag-sdk/evaluation'

const evaluator = new PrecisionEvaluator({ k: 5 })
const groundTruth = ['doc1', 'doc3']

const result = evaluator.evaluate(results, groundTruth)
// result.score = Top-5 中相关数量 / 5
```

---

### 1.3 MRR（Mean Reciprocal Rank）— `MRREvaluator`

#### 概念说明

MRR 衡量的是：第一个相关结果排在第几位。它回答的是 **"用户要翻到第几个才能看到正确答案"** 这个问题。

#### 计算公式

```
RR = 1 / 第一个相关结果的排名位置
MRR = (1/Q) × Σ RR_q  （Q 个查询的 RR 平均值）
```

#### 核心特性

- 只关心第一个相关结果，后续相关结果不影响分数
- 排名越靠前，分数越接近 1
- 如果第一个结果就相关，RR = 1.0

#### 适用场景

- 问答系统：用户只需要一个正确答案
- FAQ 系统：找到最匹配的那条 FAQ
- 精确查找：如"XX 公司的 CEO 是谁"

#### 使用示例

```typescript
import { MRREvaluator } from '@rag-sdk/evaluation'

const evaluator = new MRREvaluator()

// 第一个命中 → score = 1/1 = 1.0
evaluator.evaluate([{ id: 'doc1', ... }], ['doc1'])

// 第三个命中 → score = 1/3 ≈ 0.333
evaluator.evaluate([{ id: 'doc5' }, { id: 'doc6' }, { id: 'doc1' }], ['doc1'])

// 无命中 → score = 0
evaluator.evaluate([{ id: 'doc5' }], ['doc1'])
```

### 1.4 NDCG（Normalized Discounted Cumulative Gain）— `NDCGEvaluator`

#### 概念说明

NDCG 是最全面的检索指标，**同时考虑相关性等级和排名位置**。它回答的是："排序结果是不是接近理想的完美排序？"

#### 计算步骤

1. **DCG**：对每个位置的相关性打分，位置越后折扣越大
   ```
   DCG@K = Σ(i=1 to K) rel_i / log₂(i+1)
   ```
2. **IDCG**：按理想排序（相关性从高到低）计算的 DCG
3. **NDCG** = DCG / IDCG，范围 [0, 1]

#### 核心特性

- 需要人工标注每个结果的**相关性等级**（通常 0-3 分）
- 同时考虑了"找得准"和"排得好"
- 业界公认的最全面的排序质量指标

#### 适用场景

- 综合评估排序质量
- 搜索引擎排名算法调优
- 推荐系统排序效果评估

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `k` | `number` | `10` | 取前 K 个结果进行评测 |

#### 使用示例

```typescript
import { NDCGEvaluator } from '@rag-sdk/evaluation'

const evaluator = new NDCGEvaluator({ k: 5 })

// 同时传入 groundTruth 和 relevanceScores（可选，用于分级相关性）
const relevanceScores = new Map([
  ['doc1', 3],  // 非常相关
  ['doc3', 2],  // 相关
  ['doc4', 1],  // 部分相关
])
const result = evaluator.evaluate(results, groundTruth, relevanceScores)
```

### 1.5 ContextRelevanceEvaluator（上下文相关性）

#### 概念说明

基于 RAGAS Context Precision 指标，使用 LLM 判断检索到的每个 chunk 是否与查询相关，再通过 Average Precision（AP）聚合得到最终得分。与 Recall/Precision 等依赖 ground truth 标注的指标不同，它直接用 LLM 做裁判。

> 源码详见：`packages/evaluation/src/retrieval/context-relevance.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `llm` | `LLMProvider` | 必填 | 用于判断相关性的 LLM |

## 二、生成评测 (Generation Evaluation)

生成评测回答一个核心问题：**LLM 生成的回答质量如何？**

所有生成评测器实现 `GenerationEvaluator` 接口（定义在 `@rag-sdk/core`）：
```typescript
interface GenerationEvaluator {
  evaluate(
    answer: string,
    reference: string,
    context?: string,
  ): Promise<MetricResult> | MetricResult
}
```

> 源码详见：`packages/evaluation/src/generation/`

---

### 2.1 BLEU — `BLEUEvaluator`

#### 概念说明

BLEU（Bilingual Evaluation Understudy）通过比较生成答案和参考答案的 **n-gram 重合度**来衡量生成质量。最初用于机器翻译评测。

#### 计算步骤

1. 计算 1-gram 到 N-gram（通常 N=4）的精确率
2. 取几何平均
3. 乘以长度惩罚因子（Brevity Penalty），防止生成过短的答案

#### 核心特性

- 优点：计算快速，不需要外部模型
- 缺点：只看字面重合，不懂语义。"猫在睡觉"和"一只猫正在睡觉"得分会很低
- 适合：摘要、翻译等对措辞有要求的任务

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `maxN` | `number` | `4` | 最大 n-gram 阶数 |

#### 使用示例

```typescript
import { BLEUEvaluator } from '@rag-sdk/evaluation'

const evaluator = new BLEUEvaluator({ maxN: 4 })
const result = evaluator.evaluate('机器学习是人工智能的一个分支', '机器学习是人工智能领域的一个重要分支')
```

---

### 2.2 ROUGE — `ROUGEEvaluator`

#### 概念说明

ROUGE（Recall-Oriented Understudy for Gisting Evaluation）从**召回率视角**衡量参考答案被生成答案覆盖了多少。与 BLEU 互补——BLEU 关注精确率，ROUGE 关注召回率。

#### 变体说明

| 变体 | 说明 |
|------|------|
| ROUGE-1 | 基于单词（unigram）的重合度 |
| ROUGE-2 | 基于双词（bigram）的重合度 |
| ROUGE-L | 基于最长公共子序列（LCS），不要求连续但要求顺序一致 |

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `variant` | `'1' \| '2' \| 'L'` | `'L'` | ROUGE 变体 |

#### 使用示例

```typescript
import { ROUGEEvaluator } from '@rag-sdk/evaluation'

// ROUGE-L（最常用）
const evaluator = new ROUGEEvaluator({ variant: 'L' })
const result = evaluator.evaluate(answer, reference)
// result.details.precision, result.details.recall, result.details.f1

// ROUGE-1（单词级别）和 ROUGE-2（双词级别）
const rouge1 = new ROUGEEvaluator({ variant: '1' })
const rouge2 = new ROUGEEvaluator({ variant: '2' })
```

---

### 2.3 BERTScore — `BERTScoreEvaluator`

#### 概念说明

BERTScore 不依赖字面重合，而是用 **Embedding 的语义相似度**来评估生成质量。即使生成文本和参考文本措辞完全不同，只要语义相似就能获得高分。

#### 核心特性

- 优势：语义相似但字面不同也能得高分（如"高兴"和"开心"）
- 劣势：依赖外部 Embedding 模型，计算成本较高
- 比 BLEU/ROUGE 更接近人类判断

#### 使用示例

```typescript
import { BERTScoreEvaluator } from '@rag-sdk/evaluation'

const evaluator = new BERTScoreEvaluator(embeddingProvider)
const result = await evaluator.evaluate('这只猫正在睡觉', '小猫在休憩')
// 即使字面不同，语义相似也能得高分
```

---

### 2.4 Faithfulness（忠实度）— `FaithfulnessEvaluator`

#### 概念说明

Faithfulness 衡量的是：回答是否忠实于检索到的参考资料，**有没有编造不存在的信息**（即"幻觉"）。这是 RAG 系统最关键的评测维度之一。

#### 工作原理（RAGAS 两阶段法）

1. 将生成的回答拆分为独立的断言（claim / statement）
2. 对每个断言，用 LLM 判断是否有检索资料支撑
3. 统计有支撑的断言比例 → 忠实度分数

#### 使用示例

```typescript
import { FaithfulnessEvaluator } from '@rag-sdk/evaluation'

const evaluator = new FaithfulnessEvaluator(llmProvider)

const result = await evaluator.evaluate(
  'Python 由 Guido van Rossum 于 1991 年发布，目前是最流行的编程语言之一。',
  '',
  'Python 是一种高级编程语言，由 Guido van Rossum 创建，首次发布于 1991 年。\nPython 广泛应用于数据科学、机器学习、Web 开发等领域。',
)
// result.score < 1.0 — "目前是最流行的编程语言之一" 资料中没有提及
```

---

### 2.5 AnswerRelevance（答案相关性）— `AnswerRelevanceEvaluator`

#### 概念说明

AnswerRelevance 衡量的是：回答和用户问题有多相关，**有没有答到点上**。采用 RAGAS 的反向问题生成法：根据答案生成假设性问题，再计算这些问题与原始 query 的 TF 余弦相似度。

#### 使用示例

```typescript
import { AnswerRelevanceEvaluator } from '@rag-sdk/evaluation'

const evaluator = new AnswerRelevanceEvaluator(llmProvider)

const result = await evaluator.evaluate(
  'Python 可以通过官网下载安装包进行安装。另外 Python 是一门非常适合初学者的语言。',
  '',
  'Python 的安装方法是什么？',
)
// result.score — 与安装方法无关的"适合初学者"会降低分数
```

## 三、端到端评测 (End-to-End Evaluation)

端到端评测回答一个核心问题：**整个 RAG 系统（检索 + 生成）作为一个整体，表现如何？**

> 源码详见：`packages/evaluation/src/e2e/`

---

### 3.1 E2ELLMJudge（LLM 端到端裁判）

#### 概念说明

用一个独立的 LLM（Judge LLM）作为裁判，综合评估整个 RAG pipeline 的输出质量。它从多个维度同时打分——检索相关性、回答准确性、完整性、忠实度、有用性。

#### 评估维度

| 维度 | 说明 |
|------|------|
| 检索相关性 | 检索到的资料是否与问题相关 |
| 回答准确性 | 回答是否事实正确 |
| 完整性 | 是否覆盖了问题的所有方面 |
| 忠实度 | 回答是否基于检索资料，无幻觉 |
| 有用性 | 对用户是否有实际帮助 |

#### 关键类型

```typescript
interface E2EJudgeResult {
  scores: Record<string, number>   // 各维度评分（1-10）
  overallScore: number              // 综合评分（1-10）
  feedback: string                  // 综合评语
  dimensionReasons: Record<string, string>  // 各维度评分理由
}
```

#### 使用示例

```typescript
import { E2ELLMJudge } from '@rag-sdk/evaluation'

const judge = new E2ELLMJudge({
  judgeLLM: new OpenAIProvider({ model: 'gpt-4' }),
  dimensions: ['检索相关性', '回答准确性', '完整性', '忠实度', '有用性'],
})

const result = await judge.judge(query, answer, contexts)

console.log(result.scores)
// { '检索相关性': 8, '回答准确性': 7, '完整性': 6, '忠实度': 9, '有用性': 7 }
console.log(result.overallScore) // 7.4
console.log(result.dimensionReasons['完整性']) // "回答只涵盖了安装方法，未涉及..."
```

### 3.2 ABTestAnalyzer（A/B 测试分析）

#### 概念说明

A/B 测试通过**对比两个版本的 RAG 系统在真实用户上的表现**，判断哪个版本更好。核心是基于用户行为数据（点赞、追问、点击引用、停留时间）计算加权满意度，再进行 Z-test 统计显著性检验。

#### 用户行为指标

| 行为 | 含义 | 正向/负向 |
|------|------|-----------|
| 点赞 (thumbsUp) | 用户认为回答有帮助 | 正向 |
| 追问 (followUp) | 用户对回答不满意，继续追问 | 负向 |
| 点击引用 (sourceClick) | 用户对检索来源感兴趣 | 正向 |
| 停留时间 (dwellTime) | 用户阅读回答的时间 | 正向（适度范围内） |

#### 关键类型

```typescript
interface ABTestReport {
  satisfactionA: number    // A 组满意度均值
  satisfactionB: number    // B 组满意度均值
  countA: number           // A 组样本数
  countB: number           // B 组样本数
  zScore: number           // Z-test 统计量
  pValue: number           // p-value
  significant: boolean     // 是否有统计显著性差异
  winner: 'A' | 'B' | 'tie'
}
```

#### 使用示例

```typescript
import { ABTestAnalyzer } from '@rag-sdk/evaluation'

const analyzer = new ABTestAnalyzer()

// 收集用户行为事件
analyzer.addEvent({ group: 'A', thumbsUp: true, dwellTime: 30, sourceClick: true })
analyzer.addEvent({ group: 'A', followUp: true, dwellTime: 10 })
analyzer.addEvent({ group: 'B', thumbsUp: true, dwellTime: 45, sourceClick: true })
analyzer.addEvent({ group: 'B', thumbsUp: true, dwellTime: 50 })

const report = analyzer.analyze()

console.log('获胜方:', report.winner)          // 'B'
console.log('差异显著:', report.significant)   // true/false
console.log('p 值:', report.pValue)           // 0.03
```

### 3.3 BenchmarkRunner（批量评测）

#### 概念说明

对多个 query 并行执行评测，汇总统计结果。支持并发控制以避免 API 限流，输出各指标的平均值、标准差、最小/最大值。统一处理检索评测和生成评测。

#### 关键类型

```typescript
interface BenchmarkReport {
  metrics: Record<string, MetricStats>  // 各指标的统计汇总
  perSample: Array<Record<string, number>>  // 每个样本的各指标得分
  totalSamples: number
  evaluators: string[]
  timestamp: string
}

interface MetricStats {
  mean: number   // 平均值
  std: number    // 标准差
  min: number    // 最小值
  max: number    // 最大值
}
```

#### 使用示例

```typescript
import {
  BenchmarkRunner,
  RecallEvaluator,
  PrecisionEvaluator,
  MRREvaluator,
  NDCGEvaluator,
} from '@rag-sdk/evaluation'

// 同时评测检索和生成
const runner = new BenchmarkRunner({
  retrievers: [myRetriever],
  generators: [myGenerator],
  evaluators: [
    new RecallEvaluator({ k: 5 }),
    new PrecisionEvaluator({ k: 5 }),
    new MRREvaluator(),
    new NDCGEvaluator({ k: 5 }),
  ],
  concurrency: 3,
})

const report = await runner.run(dataset)

console.log('各指标统计:', report.metrics)
// { 'Recall@K': { mean: 0.75, std: 0.12, min: 0.5, max: 0.95 }, ... }
```

### 3.4 EvaluationReport（评测报告生成）

#### 概念说明

将检索评测、生成评测、端到端评测的结果汇总为一份完整的结构化报告，包含各指标统计、改进建议和阈值建议。支持 JSON 格式输出，方便归档和自动化分析。

#### 关键类型

```typescript
interface FullReport {
  timestamp: string
  summary: {
    totalSamples: number
    overallScore: number
    verdict: string
  }
  retrieval?: BenchmarkReport
  generation?: BenchmarkReport
  e2e?: {
    llmJudgeScores?: Record<string, number>
    abTest?: ABTestReport
  }
  recommendations: string[]
}
```

#### 使用示例

```typescript
import { EvaluationReport, BenchmarRunner, E2ELLMJudge } from '@rag-sdk/evaluation'

// 1. 执行批量评测
const runner = new BenchmarkRunner({ ... })
const benchmarkReport = await runner.run(dataset)

// 2. 执行 E2E 评测
const judge = new E2ELLMJudge({ judgeLLM })
const judgeResults = await Promise.all(testCases.map(tc => judge.judge(...)))

// 3. 汇总生成报告
const report = new EvaluationReport()
report.setBenchmarkReport(benchmarkReport)
report.setLLMJudgeResults(judgeResults)

const fullReport = report.generate()
// fullReport.summary.verdict => "良好：系统表现良好，有优化空间"
// fullReport.recommendations => ["召回率偏低，建议增加文档覆盖范围", ...]
```
