### 2.3 设计原则

- **无循环依赖**：依赖关系形成严格的有向无环图（DAG）
- **core 零依赖**：core 包不依赖任何其他包，确保稳定性
- **adapter 可选**：有外部依赖的适配器已拆分为独立包（如 `@ragsdk/llm-anthropic`、`@ragsdk/storage-pinecone`），用户按需安装；OpenAI 适配器因零外部依赖保留在主包中
- **接口隔离**：跨包通信只通过 core 中定义的接口和类型

## 3. Pipeline 编排设计

### 3.1 RAGPipeline 核心入口

`RAGPipeline` 是整个 SDK 的核心入口，负责编排从文档导入到答案生成的完整流程。

```ts
interface RAGPipelineConfig {
  // 必需组件
  llm: LLM;
  embedding: EmbeddingModel;
  store: VectorStore;

  // 可选组件（提供默认实现）
  chunker?: Chunker;                    // 默认 RecursiveChunker
  retriever?: Retriever;                // 默认 VectorRetriever
  postProcessors?: PostProcessor[];     // 默认为空
  generator?: Generator;                // 默认 GroundedGenerator（原设计 GroundingGenerator）
  queryTransformer?: QueryTransformer;  // 默认为空（不转换）

  // 可选的高级组件
  graphStore?: GraphStore;              // 知识图谱存储
  loaders?: DocumentLoader[];           // 文档加载器

  // 配置
  monitor?: PipelineMonitor;            // 生命周期监控（原设计 PipelineHooks，实际实现更名）
}
```

### 3.2 Pipeline 阶段划分

Pipeline 分为两个主要流程：**导入流程（Ingestion）** 和 **查询流程（Query）**。

#### 导入流程（Ingestion Pipeline）

```
文档输入 → 文档加载 → 文档清洗 → 文档切块 → Embedding → 向量存储
              ↓           ↓          ↓          ↓          ↓
          Loader     Cleaner    Chunker    Embedding   VectorStore
```

```ts
// 导入流程的 Stage 定义
class IngestionStage implements PipelineStage<RawDocument[], void> {
  async execute(
    input: RawDocument[],
    context: PipelineContext,
  ): Promise<void> {
    const loaded = await this.loadDocuments(input);
    const cleaned = await this.cleanDocuments(loaded);
    const chunks = await this.chunkDocuments(cleaned);
    const embeddings = await this.embedChunks(chunks);
    await this.storeVectors(embeddings);
  }
}
```

#### 查询流程（Query Pipeline）

```
用户查询 → Query Transform → 检索 → 后处理 → Prompt 构建 → LLM 生成 → 答案后处理
              ↓               ↓        ↓          ↓            ↓           ↓
         QueryTransformer Retriever  PostProc   Template     LLM        Formatter
```

```ts
// 查询流程的 Stage 定义
class QueryStage implements PipelineStage<Query, QueryResult> {
  async execute(
    input: Query,
    context: PipelineContext,
  ): Promise<QueryResult> {
    const transformedQuery = await this.transformQuery(input);
    const retrieved = await this.retrieve(transformedQuery);
    const processed = await this.postProcess(retrieved);
    const prompt = await this.buildPrompt(processed, input);
    const answer = await this.generate(prompt);
    return this.formatResult(answer, processed);
  }
}
```

### 3.3 中间件 / Hooks 系统

Pipeline 支持在每个阶段前后插入自定义逻辑：

```ts
interface PipelineHooks {
  // 导入流程钩子
  beforeIngest?: (docs: RawDocument[]) => RawDocument[] | Promise<RawDocument[]>;
  afterIngest?: (chunks: Chunk[]) => void | Promise<void>;

  // 查询流程钩子
  beforeQuery?: (query: Query) => Query | Promise<Query>;
  afterRetrieve?: (results: RetrievedChunk[]) => RetrievedChunk[] | Promise<RetrievedChunk[]>;
  beforeGenerate?: (prompt: string, context: RetrievedChunk[]) => string | Promise<string>;
  afterGenerate?: (result: QueryResult) => QueryResult | Promise<QueryResult>;

  // 全局钩子
  onError?: (error: Error, stage: string, context: PipelineContext) => void;
  onProgress?: (event: ProgressEvent) => void;
}
```

> **⚠️ 设计变更**：实际实现中 `PipelineHooks` 被 `PipelineMonitor`（位于 `@ragsdk/core`）替代，采用更轻量的回调模式。`PipelineMonitor` 提供各阶段的耗时统计和生命周期回调，而非在每个阶段前后拦截数据。

使用示例：

```ts
const rag = new RAGPipeline({
  // ... 其他配置
  hooks: {
    // 查询前自动添加时间上下文
    beforeQuery: (query) => ({
      ...query,
      text: `[当前时间: ${new Date().toISOString()}] ${query.text}`,
    }),

    // 检索后过滤低分结果
    afterRetrieve: (results) =>
      results.filter((r) => r.score > 0.7),

    // 全局错误处理
    onError: (error, stage) => {
      logger.error(`Pipeline stage "${stage}" failed:`, error);
    },

    // 进度通知
    onProgress: (event) => {
      console.log(`[${event.stage}] ${event.message} (${event.progress}%)`);
    },
  },
});
```

```

### 4.2 数据流中的类型流转

```
// 导入流程数据类型流转
RawDocument[]
  → CleanedDocument[]     （清洗后）
    → Chunk[]             （切块后，携带 parentDoc 和 position 元数据）
      → EmbeddedChunk[]   （添加 embedding 向量后）
        → 存入 VectorStore

// 查询流程数据类型流转
Query { text: string, filters?: MetadataFilter }
  → TransformedQuery { queries: string[], embedding?: number[] }
    → RetrievedChunk[] { chunk: Chunk, score: number, source: string }
      → ProcessedChunk[] { chunk: Chunk, score: number, rerankScore?: number }
        → QueryResult { answer: string, sources: Source[], confidence: number }
```

                    │    知识图谱构建           │

  RawDocument ─────▶│  实体抽取 + 关系抽取     │
                    │         ↓                │
                    │  GraphStore（图存储）     │
                    └──────────┬───────────────┘
                               │
                    ┌──────────▼───────────────┐
                    │    图增强检索             │
                    │                          │
  Query ───────────▶│  图检索（关联实体查找）   │
                    │         ↓                │

                    │         ↓                │

                    └──────────────────────────┘
```

> 以下是原设计文档中的类名与实际实现类名的对照表，方便开发者理解对应关系。

#### 类名变更

| 原设计名称 | 实际实现名称 | 所在包 | 说明 |
|-----------|------------|--------|------|
| `FusionRetriever` | `FusionSearch` | `@ragsdk/retrieval` | 命名风格统一为 Search 后缀 |
| `Reranker` | `RerankerPostProcessor` | `@ragsdk/retrieval` | 明确标注为 PostProcessor |
| `HyDEQueryTransformer` | `HyDETransformer` | `@ragsdk/retrieval` | 简化命名 |
| `GroundingGenerator` | `GroundedGenerator` | `@ragsdk/generation` | 命名风格调整 |
| `ContextEnhancer` | `DocumentAugmenter` | `@ragsdk/document` | 语义更准确 |
| `IncrementalUpdater` | `IndexManager` | `@ragsdk/storage` | 职责范围扩大 |
| `E2EEvaluator` | `E2ELLMJudge` | `@ragsdk/evaluation` | 强调 LLM 评判机制 |
| `RelevanceEvaluator` | `AnswerRelevanceEvaluator` | `@ragsdk/evaluation` | 明确评测对象 |
| `ReportGenerator` | `EvaluationReport` | `@ragsdk/evaluation` | 从生成器改为报告实体 |
| `ComparisonRunner` | `BenchmarkRunner` | `@ragsdk/evaluation` | 语义更通用 |

| `AdvancedRAG`（类） | `createAdvancedRAG()`（工厂函数） | `rag-sdk` | 改用工厂函数模式 |

| `ContextCompressor` | `CompressionPostProcessor` | `@ragsdk/retrieval` | 明确为后处理器 |

#### 不实现的功能

| 原设计名称 | 替代方案 | 原因 |
|-----------|---------|------|
| `RedundancyFilter` | `SelectiveContextPostProcessor` + `RerankerPostProcessor` | 功能冗余，组合替代 |
| `MMRRetriever` | `RRFSearch` + `RerankerPostProcessor` | MMR 效果可由 RRF + 重排序组合达到 |
| `CoherenceEvaluator` | `ConsistencyChecker`（generation）+ `FaithfulnessEvaluator` + `AnswerRelevanceEvaluator` | 连贯性可拆解为一致性 + 忠实度 + 相关性的组合 |
| `GraphRAG`（预设） | `PipelineBuilder` + `GraphEnhancedRetriever` | 不作为独立预设，通过组合方式灵活构建 |
| `DatasetLoader` | 仅定义类型（`evaluation/src/types.ts`） | 评测数据集加载留给用户自定义 |

#### 设计决策变更

| 变更项 | 原设计 | 实际实现 | 原因 |
|--------|--------|---------|------|
| Token 计数 | tiktoken（精确分词） | `CharBasedTokenCounter`（字符近似） | 减少外部依赖，简化部署 |
| Pipeline 监控 | `PipelineHooks`（阶段拦截） | `PipelineMonitor`（回调模式） | 更轻量，不侵入数据流 |
| 流式输出 | SSE 流式 | `queryStream` 真正 `AsyncIterable` | 更原生的 Node.js 流式支持 |

### 7.3 配置说明

| 配置项 | 说明 |
|--------|------|
| `dependsOn: ["^build"]` | 构建当前包前，先构建其依赖的内部包（拓扑排序） |
| `inputs` | 影响缓存键的文件列表，只有这些文件变化时才重新执行 |
| `outputs` | 构建产物目录，用于缓存恢复 |
| `cache: true` | 启用远程/本地缓存，未变更时跳过执行 |
| `persistent: true` | 标记为长期运行任务（如 dev server），不会被其他任务等待 |

### 8.3 各子包独立发布策略

#### 版本管理

使用 [Changesets](https://github.com/changesets/changesets) 管理版本和 CHANGELOG：

```bash
# 开发者在提交 PR 时创建 changeset
pnpm changeset

# CI 自动根据 changeset 计算版本号并发布
pnpm release
```

#### 发布流程

```
1. 开发者提交代码 + changeset 文件（.changeset/*.md）
   ↓
2. CI 运行测试（vitest）+ lint（eslint）+ 类型检查（tsc）
   ↓
3. 合并到 main 分支时，CI 检测 changeset
   ↓
4. Release PR 自动创建，包含版本升级和 CHANGELOG
   ↓
5. 维护者审核后合并 Release PR
   ↓
6. 自动发布到 npm（各子包独立版本号）
```

#### 包发布顺序

由于内部包存在依赖关系，Turborepo 会自动按拓扑排序决定发布顺序：

```
1. @ragsdk/core           （无依赖，最先发布）
2. @ragsdk/llm            （依赖 core）
   @ragsdk/embedding      （依赖 core，可与 llm 并行）
   @ragsdk/storage        （依赖 core，可与 llm 并行）
3. @ragsdk/document       （依赖 core + embedding）
   @ragsdk/retrieval      （依赖 core + embedding + storage）
   @ragsdk/indexing       （依赖 core + document + embedding + storage）
   @ragsdk/generation     （依赖 core + llm）
   @ragsdk/evaluation     （依赖 core + llm）
   @ragsdk/knowledge-graph（依赖 core + llm + storage）
4. @ragsdk/llm-anthropic       （依赖 core + llm）
   @ragsdk/llm-google           （依赖 core + llm）
   @ragsdk/embedding-anthropic  （依赖 core + embedding）
   @ragsdk/embedding-google     （依赖 core + embedding）
   @ragsdk/embedding-voyage     （依赖 core + embedding）
   @ragsdk/storage-pinecone     （依赖 core + storage）
   @ragsdk/storage-weaviate     （依赖 core + storage）
   @ragsdk/storage-chroma       （依赖 core + storage）
   @ragsdk/storage-qdrant       （依赖 core + storage）
5. rag-sdk                 （依赖所有子包，最后发布）
```

#### 用户安装方式

```bash
# 方式一：安装主包（包含所有功能）
npm install rag-sdk

# 方式二：按需安装子包（减小包体积）
npm install @ragsdk/core @ragsdk/llm @ragsdk/storage @ragsdk/retrieval @ragsdk/generation

# 方式三：按需安装外部适配器包（需同时安装对应的外部 SDK）
npm install @ragsdk/llm-anthropic @anthropic-ai/sdk     # Anthropic Claude
npm install @ragsdk/llm-google @google/generative-ai     # Google Gemini
npm install @ragsdk/storage-pinecone @pinecone-database/pinecone  # Pinecone
npm install @ragsdk/storage-chroma chromadb              # ChromaDB

# 安装内置 OpenAI 适配器（已包含在主包中，无需额外安装）
npm install openai
```
