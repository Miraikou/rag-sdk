# 生成模块

> 本文档描述生成模块的设计理念和各生成器的职责。具体 API 签名和使用方式请参考对应源码文件中的 JSDoc 注释。

生成模块是 RAG 系统的最终环节，负责将检索到的内容与用户问题一起组装成 prompt，调用 LLM 生成最终回答，并对回答质量进行保障和评估。

---

## 1. BasePromptTemplate（提示词模板）

### 概念说明

将检索到的文档内容和用户问题按照固定格式组装成 prompt，送入 LLM 生成回答。提示词模板决定了 LLM 如何理解任务、如何使用提供的上下文。

### 解决的问题

- 统一的 prompt 格式管理，避免各处拼接逻辑不一致
- 内置经过验证的最佳实践模板，减少 prompt 工程成本
- 支持变量插值 `{query}` 和 `{context}`，灵活适配不同场景

> 源码详见：`packages/generation/src/prompt-template.ts`

### 关键接口

```typescript
interface PromptTemplate {
  format(query: string, chunks: Chunk[], options?: FormatOptions): Message[]
}
```

`BasePromptTemplate` 实现 `PromptTemplate` 接口，支持 `{query}`、`{context}` 占位符变量插值。

### 内置预设模板

| 预设 | 说明 |
|------|------|
| **默认模板** | 标准 RAG prompt：基于上下文回答问题，不知道就说不知道 |
| **Strict 模板** | 严格模式：必须逐句引用来源，禁止添加上下文之外的信息 |
| **Citation 模板** | 引用模式：回答中标注 `[1]`、`[2]` 引用来源 |

### 使用示例

```typescript
import { BasePromptTemplate } from '@rag-sdk/generation'

// 使用内置模板
const template = new BasePromptTemplate(
  '你是一个专业的答疑助手。请仅基于提供的上下文回答问题。',
  '用户问题：{query}\n\n参考资料：\n{context}',
)

// 自定义模板
const customTemplate = new BasePromptTemplate(
  '你是法律顾问，请基于提供的法律条款给出建议。如果无法确定，请明确说明。',
  '咨询问题：{query}\n\n相关条款：\n{context}',
)

const messages = template.format(query, chunks, { maxContextLength: 4000 })
```

## 2. StandardGenerator（标准生成器）

### 概念说明

调用 LLM 基于检索结果生成最终回答。`StandardGenerator` 是 RAG 管道的基础生成器，将 `PromptTemplate` 组装好的 prompt 送入 LLM，获取结构化的生成结果。

### 解决的问题

- 将 prompt 模板 + LLM 调用封装为统一的生成接口
- 同时支持同步（`generate`）和流式（`generateStream`）生成
- 返回结构化的 `GenerateResult`（包含 answer + sources + metadata）

> 源码详见：`packages/generation/src/generator.ts`

### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `promptTemplate` | `string` | 内置 | 自定义 Prompt 模板，支持 `{query}` `{context}` 占位符 |
| `maxTokens` | `number` | LLM 默认值 | 最大生成 token 数 |
| `includeSources` | `boolean` | `true` | 是否在结果中包含引用来源 |

### 使用示例

```typescript
import { StandardGenerator, BasePromptTemplate } from '@rag-sdk/generation'

const generator = new StandardGenerator(llmProvider)

// 基础生成
const result = await generator.generate('TypeScript 是什么？', chunks)
console.log(result.answer)
console.log(result.sources) // 引用的来源列表

// 使用自定义模板
const customGenerator = new StandardGenerator(llmProvider, customTemplate)
const result2 = await customGenerator.generate(query, chunks, {
  maxTokens: 500,
  includeSources: true,
})

// 流式生成
for await (const token of generator.generateStream('解释这个概念', chunks)) {
  process.stdout.write(token)
}
```

## 3. GroundedGenerator（接地生成）

### 概念说明

确保 LLM 的回答完全基于检索到的内容，防止 LLM 编造不存在的信息（即"幻觉"问题）。接地通过两个层面实现：
1. **生成时** — prompt 中明确要求"仅基于提供的上下文回答"
2. **生成后** — LLM 验证答案中是否有上下文之外的信息（幻觉检测）

### 解决的问题

- LLM 在信息不足时可能编造看似合理但实际不存在的答案
- 在医疗、法律等高风险领域，幻觉可能导致严重后果
- 需要对生成内容进行可追溯的归因验证

> 源码详见：`packages/generation/src/grounding.ts`

### 关键类型

```typescript
// 接地验证结果
interface GroundingVerification {
  isGrounded: boolean          // 答案是否完全基于上下文
  unsupportedClaims: string[]  // 无法从上下文支持的声明
  groundingScore: number       // 接地分数（0-1）
}

// 接地生成结果
interface GroundedGenerateResult extends GenerateResult {
  verification: GroundingVerification
}
```

### 使用示例

```typescript
import { GroundedGenerator } from '@rag-sdk/generation'

const generator = new GroundedGenerator(baseGenerator, llmProvider)

const result = await generator.generate('这个药物的副作用是什么？', chunks)

console.log(`接地分数: ${result.verification.groundingScore}`)
if (!result.verification.isGrounded) {
  console.log('警告：以下声明无法从文档中验证：')
  result.verification.unsupportedClaims.forEach((c) => console.log(`  - ${c}`))
}
```

## 4. CitationGenerator（引用生成）

### 概念说明

在答案中自动标注引用来源，指明每段信息来自哪个文档的哪个片段。`CitationGenerator` 输出的答案中包含 `[1]`、`[2]` 等引用标注，并在答案末尾附上来源列表。

### 解决的问题

- 用户需要验证答案的可信度，追溯信息来源
- 合规场景要求每段回答必须有据可查
- 提升 RAG 系统的透明度和可解释性

> 源码详见：`packages/generation/src/citation.ts`

### 关键类型

```typescript
// 引用生成结果
interface CitationGenerateResult extends GenerateResult {
  citedAnswer: string     // 带引用标注的答案文本
  sourceList: string      // 来源列表文本
}
```

### 使用示例

```typescript
import { CitationGenerator } from '@rag-sdk/generation'

const generator = new CitationGenerator(llmProvider)

const result = await generator.generate('公司的年假政策是什么？', chunks)

console.log(result.citedAnswer)
// "根据员工手册，公司年假为15天[1]。工龄满5年可额外获得3天年假[2]。"
```

## 5. SelfRAGGenerator（自反思生成）

### 概念说明

`SelfRAGGenerator` 在生成过程中进行多轮自反思，包含三个决策点：
1. **是否需要检索**（Retrieve token）— 判断问题是否需要用外部知识
2. **检索结果是否相关**（Relevance token）— 判断检索到的内容是否与问题相关
3. **生成答案是否忠实**（Support token）— 判断答案是否有上下文支撑

根据反思结果决定是否重新检索或重新生成，直到生成满意的答案。

### 解决的问题

- 无法提前知道检索是否足够 —— Self-RAG 动态判断
- 检索到的内容可能与问题不相关 —— 自动触发重新检索
- 生成的答案可能偏离上下文 —— 忠实度检查后重新生成

> 源码详见：`packages/generation/src/self-rag.ts`

### 关键类型

```typescript
interface ReflectionTokens {
  needsRetrieval: boolean      // 是否需要检索
  retrievalRelevant: boolean   // 检索结果是否相关
  answerFaithful: boolean      // 答案是否忠实于上下文
}

interface SelfRAGResult extends GenerateResult {
  reflection: ReflectionTokens
  regenerated: boolean         // 是否经过重新生成
  rounds: number               // 总轮数
}
```

### 使用示例

```typescript
import { SelfRAGGenerator } from '@rag-sdk/generation'

const generator = new SelfRAGGenerator(llmProvider, retriever)

const result = await generator.generate('最新版本的 React 有哪些新特性？', chunks)

console.log(`反思结果:`)
console.log(`  需要检索: ${result.reflection.needsRetrieval}`)
console.log(`  检索相关: ${result.reflection.retrievalRelevant}`)
console.log(`  答案忠实: ${result.reflection.answerFaithful}`)
console.log(`  总轮数: ${result.rounds}`)
```

## 6. ConsistencyChecker（一致性检测）

### 概念说明

对同一问题多次生成回答，比较多次生成结果之间的一致性。一致性高的答案更可信，一致性低的说明 LLM 对该问题存在不确定性。

### 解决的问题

- LLM 的随机性（temperature > 0）导致同一问题可能给出不同答案
- 高一致性 → 模型对该知识有确定理解
- 低一致性 → 模型在猜测，答案不可靠

> 源码详见：`packages/generation/src/consistency.ts`

### 关键类型

```typescript
interface ConsistencyResult {
  answers: string[]            // 多次生成的答案列表
  consistencyScore: number     // 一致性分数（0-1，1 表示完全一致）
  bestAnswer: string           // 最佳答案
  conflicts: string[]          // 冲突点列表
}
```

### 使用示例

```typescript
import { ConsistencyChecker } from '@rag-sdk/generation'

const checker = new ConsistencyChecker(generator, { rounds: 3 })

const result = await checker.check('公司的报销流程是什么？', chunks)

console.log(`一致性分数: ${result.consistencyScore}`)
console.log(`最佳答案: ${result.bestAnswer}`)
if (result.conflicts.length > 0) {
  console.log('发现冲突点:', result.conflicts)
}
```
