# 知识图谱模块

> 本文档描述知识图谱模块的设计理念和模块架构。具体 API 签名和使用方式请参考对应源码文件中的 JSDoc 注释。

---

## 一、概述

### 1.1 什么是知识图谱

知识图谱（Knowledge Graph）是一种**用图结构表示实体及其关系**的数据模型。在 RAG 系统中，它把非结构化文档中的知识抽取为结构化的三元组（实体-关系-实体），形成一张语义网络。

### 1.2 解决什么问题

传统向量检索只能找到与 query **语义相似**的文档段落，但无法处理需要**多步推理**的问题：

| 场景 | 向量检索 | 知识图谱 |
|------|----------|----------|
| "A 公司的 CEO 是谁？" | 能找到包含该信息的段落 | 直接返回关系 |
| "A 公司 CEO 毕业于哪所大学？" | 需要两段信息拼接，难以完成 | A → CEO → 人 → 毕业 → 大学 |
| "哪些公司使用了 X 技术？" | 可能遗漏间接关联 | 沿关系链遍历，不遗漏 |

### 1.3 适用场景

- 需要回答实体关系的问题（"谁管理谁"、"属于哪个部门"）
- 多跳推理（A→B→C 链条式问题）
- 需要全局视角的查询（"公司所有项目的技术栈"）
- 需要结合向量检索做混合检索的场景

### 1.4 核心类型

知识图谱的核心数据结构定义在 `packages/knowledge-graph/src/types.ts`，基础类型（`Document`、`LLMProvider` 等）复用自 `@rag-sdk/core`：

```typescript
// 实体
interface Entity {
  id: string
  name: string
  type: string        // 实体类型（人物、组织、产品、地点、概念等）
  metadata: Record<string, unknown>
}

// 关系
interface Relation {
  source: string       // 源实体 ID
  target: string       // 目标实体 ID
  type: string         // 关系类型
  metadata: Record<string, unknown>
}

// 抽取结果
interface GraphData {
  entities: Entity[]
  relations: Relation[]
}
```

## 二、实体关系抽取 (EntityExtractor)

### 2.1 概念说明

实体关系抽取是知识图谱构建的第一步：用 LLM 从非结构化文档中**自动提取实体和关系**，输出结构化的图数据。

### 2.2 核心概念

- **实体 (Entity)**：文档中提到的具体事物，如人物、组织、产品、地点、概念等
- **关系 (Relation)**：实体之间的联系，如"管理"、"属于"、"依赖"、"位于"等
- **三元组**：`(源实体, 关系, 目标实体)` — 知识图谱的基本单元

> 源码详见：`packages/knowledge-graph/src/entity-extractor.ts`

### 2.3 使用示例

```typescript
import { EntityExtractor } from '@rag-sdk/knowledge-graph'

const extractor = new EntityExtractor({ llmProvider })

const document = {
  id: 'doc-001',
  content: `
    张三是ABC科技有限公司的CEO，他于2015年创立了该公司。
    ABC科技位于北京市海淀区，主要从事人工智能技术的研发。
    公司的核心产品是"智析"数据分析平台，该平台使用了深度学习技术。
    李四是ABC科技的CTO，负责技术团队的管理。
  `,
}

const graphData = await extractor.extract(document)

console.log(graphData.entities)
// [
//   { id: 'entity_张三', name: '张三', type: '人物', ... },
//   { id: 'entity_abc科技', name: 'ABC科技有限公司', type: '组织', ... },
//   { id: 'entity_智析', name: '智析', type: '产品', ... },
//   ...
// ]

console.log(graphData.relations)
// [
//   { source: 'entity_张三', target: 'entity_abc科技', type: '创建', ... },
//   { source: 'entity_abc科技', target: 'entity_智析', type: '包含', ... },
//   { source: 'entity_智析', target: 'entity_深度学习', type: '使用', ... },
//   ...
// ]
```

### 2.4 自定义实体和关系类型

```typescript
// 针对法律领域的自定义配置
const legalExtractor = new EntityExtractor({
  llmProvider,
  entityTypes: ['法规', '条款', '机构', '行为', '处罚'],
  relationTypes: ['依据', '违反', '适用', '管辖', '处罚'],
})

// 自定义 prompt
const customExtractor = new EntityExtractor({
  llmProvider,
  extractPrompt: `请从以下文档中提取技术架构相关的实体和关系...`,
})
```

## 三、图存储 (GraphStore)

### 3.1 概念说明

`GraphStore` 是存储和查询图数据的抽象层。它定义了图操作的统一接口，支持多种底层实现（内存、数据库等），使得上层业务代码不依赖具体的存储引擎。

> 接口定义详见：`packages/knowledge-graph/src/types.ts` 中的 `GraphStore` 接口

### 3.2 接口概览

| 方法 | 说明 |
|------|------|
| `addEntities(entities)` | 批量添加实体 |
| `addRelations(relations)` | 批量添加关系 |
| `getEntity(entityId)` | 根据 ID 获取实体，不存在返回 `null` |
| `getNeighbors(entityId, options?)` | 获取实体的邻居（支持跳数、类型过滤、数量限制） |
| `findPath(sourceId, targetId)` | 查找两个实体之间的最短路径（BFS） |
| `query(query)` | 自然语言关键词查询图数据 |

### 3.3 MemoryGraphStore（内存图存储）

基于邻接表的内存图存储实现，适用于开发调试和中小规模数据。

> 源码详见：`packages/knowledge-graph/src/graph-store.ts`

### 3.4 Neo4jGraphStore（接口预留）

Neo4j 图数据库适配器，接口已定义但尚未实现具体逻辑。

> 源码详见：`packages/knowledge-graph/src/graph-store.ts`

### 3.5 使用示例

```typescript
import { MemoryGraphStore } from '@rag-sdk/knowledge-graph'

const store = new MemoryGraphStore()

// 添加实体
await store.addEntities([
  { id: 'e1', name: '张三', type: '人物', metadata: {} },
  { id: 'e2', name: 'ABC科技', type: '组织', metadata: {} },
  { id: 'e3', name: '智析平台', type: '产品', metadata: {} },
  { id: 'e4', name: '深度学习', type: '技术', metadata: {} },
  { id: 'e5', name: '李四', type: '人物', metadata: {} },
])

// 添加关系
await store.addRelations([
  { source: 'e1', target: 'e2', type: '创建', metadata: {} },
  { source: 'e2', target: 'e3', type: '包含', metadata: {} },
  { source: 'e3', target: 'e4', type: '使用', metadata: {} },
  { source: 'e5', target: 'e2', type: '属于', metadata: {} },
])

// 查询实体
const entity = await store.getEntity('e1')
console.log(entity?.name) // '张三'

// 查询邻居（1 跳）
const neighbors = await store.getNeighbors('e2')
console.log(neighbors.entities.map((e) => e.name))
// ['张三', '智析平台', '李四']

// 查询邻居（2 跳，仅人物）
const deepNeighbors = await store.getNeighbors('e2', {
  hops: 2,
  entityTypes: ['人物'],
})

// 查找路径
const path = await store.findPath('e1', 'e4')
console.log(path.map((e) => e.name))
// ['张三', 'ABC科技', '智析平台', '深度学习']

// 关键词查询
const result = await store.query('深度学习 产品')
console.log(result.entities.map((e) => e.name))
// ['智析平台', '深度学习']
```

## 四、图检索 (GraphRetriever)

### 4.1 概念说明

`GraphRetriever` 基于知识图谱进行检索。它从用户问题中识别实体，在图中沿关系链扩展，找到与问题相关的结构化知识，并将其转换为与其他检索器兼容的 `SearchResult` 格式。`GraphRetriever` 实现 `Retriever` 接口，可直接与其他检索器组合使用。

### 4.2 检索方式

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| 实体匹配 | 找到 query 中提到的实体，返回相关子图 | 直接查询实体信息 |
| 多跳查询 | 从实体出发，沿关系链扩展 N 跳 | 多步推理问题 |
| 路径查询 | 找两个实体之间的关系路径 | "A 和 B 是什么关系" |

> 源码详见：`packages/knowledge-graph/src/graph-retriever.ts`

### 4.3 使用示例

```typescript
import { GraphRetriever, MemoryGraphStore } from '@rag-sdk/knowledge-graph'

const graphStore = new MemoryGraphStore()
// ... 添加实体和关系

const retriever = new GraphRetriever({
  graphStore,
  llmProvider,
  maxHops: 2,
  maxEntities: 10,
})

// 查询：会自动提取"ABC科技"实体，并沿关系链扩展
const results = await retriever.retrieve('ABC科技的核心产品使用了什么技术？')

for (const result of results) {
  console.log(`[${result.score.toFixed(2)}] ${result.content}`)
}
// [0.80] 实体：ABC科技（类型：组织）
//        关系：张三 --[创建]--> ABC科技
//        ABC科技 --[包含]--> 智析平台
// [0.70] 实体：智析平台（类型：产品）
//        关系：ABC科技 --[包含]--> 智析平台
//        智析平台 --[使用]--> 深度学习
```

## 五、图增强检索 (GraphEnhancedRetriever)

### 5.1 概念说明

`GraphEnhancedRetriever` 是一个**混合检索器**，同时利用向量检索（语义相似）和图检索（结构化推理）的优势，将两者的结果合并排序后返回。

### 5.2 工作流程

```
用户 Query
    │
    ├──→ 向量检索器 ──→ 语义相关 Chunks ──→ 向量结果
    │
    └──→ 图检索器 ──→ 结构化知识 ──→ 图结果
            │
            │  从 Chunks 中提取实体
            │  在知识图谱中扩展
            │
    合并 + 加权排序 ──→ 最终结果
```

> 源码详见：`packages/knowledge-graph/src/graph-enhanced-retriever.ts`

### 5.3 使用示例

```typescript
import {
  GraphEnhancedRetriever,
  GraphRetriever,
  MemoryGraphStore,
} from '@rag-sdk/knowledge-graph'

const enhancedRetriever = new GraphEnhancedRetriever({
  vectorRetriever,    // 标准向量检索器
  graphRetriever,     // 图检索器
  graphStore,         // 图存储
  llmProvider,
  vectorWeight: 0.6,  // 向量结果权重
  graphWeight: 0.4,   // 图结果权重
  topK: 5,
})

// 执行混合检索
const results = await enhancedRetriever.retrieve(
  'ABC科技的CTO管理的技术团队使用了哪些技术？',
)

for (const result of results) {
  console.log(
    `[${result.score.toFixed(2)}] [${result.metadata?.source}] ${result.content.substring(0, 100)}...`,
  )
}
// [0.85] [vector] 李四是ABC科技的CTO，负责管理公司的技术团队...
// [0.72] [knowledge_graph] 实体：李四（类型：人物）关系：李四 --> ABC科技
// [0.68] [graph_expansion] 实体：ABC科技（类型：组织）关联实体：智析平台、张三...
// [0.55] [vector] ABC科技的智析平台采用了深度学习和自然语言处理技术...
```

## 六、图构建 Pipeline (GraphBuilder)

### 6.1 概念说明

`GraphBuilder` 提供从文档批量构建知识图谱的完整流水线。它协调实体抽取、去重合并、存储入库等步骤，并生成构建报告。

### 6.2 工作流程

```
文档列表
    │
    ▼
[1] 逐文档实体关系抽取（EntityExtractor）
    │
    ▼
[2] 实体去重与合并（同名实体合并元数据）
    │
    ▼
[3] 关系去重（相同 source + target + type 的关系合并）
    │
    ▼
[4] 批量存入 GraphStore
    │
    ▼
构建报告（BuildReport）
```

> 源码详见：`packages/knowledge-graph/src/graph-builder.ts`

### 6.3 构建报告

```typescript
interface BuildReport {
  entityCount: number        // 最终实体数量
  relationCount: number      // 最终关系数量
  documentCount: number      // 处理的文档数量
  errors: string[]           // 构建过程中的错误
  perDocument: Array<{       // 每个文档的抽取统计
    documentId: string
    entityCount: number
    relationCount: number
    error?: string
  }>
  durationMs: number         // 构建耗时（毫秒）
}
```

### 6.4 使用示例

```typescript
import { EntityExtractor, MemoryGraphStore, GraphBuilder } from '@rag-sdk/knowledge-graph'

// 1. 创建组件
const extractor = new EntityExtractor({
  llmProvider,
  entityTypes: ['人物', '组织', '产品', '技术', '地点'],
  relationTypes: ['管理', '创建', '属于', '使用', '位于', '包含'],
})

const graphStore = new MemoryGraphStore()

// 2. 创建构建器
const builder = new GraphBuilder({
  extractor,
  graphStore,
  concurrency: 3,     // 并发处理文档数
  timeoutMs: 30000,   // 单文档超时
})

// 3. 准备文档
const documents = [
  { id: 'doc-001', content: '张三是ABC科技的创始人兼CEO。公司位于北京，主要产品是智析平台。' },
  { id: 'doc-002', content: 'ABC科技的CTO是李四，他带领团队开发了智析平台。该平台使用了深度学习技术。' },
  { id: 'doc-003', content: '智析平台是ABC科技的旗舰产品，支持数据分析和机器学习两大核心功能。' },
]

// 4. 执行构建
const report = await builder.buildFromDocuments(documents)

console.log('构建完成！')
console.log(`实体数: ${report.entityCount}`)    // 如: 8
console.log(`关系数: ${report.relationCount}`)  // 如: 12
console.log(`文档数: ${report.documentCount}`)  // 3
console.log(`错误数: ${report.errors.length}`)  // 0
console.log(`耗时: ${report.durationMs}ms`)      // 如: 5230ms

// 查看每个文档的抽取统计
for (const stat of report.perDocument) {
  console.log(`  ${stat.documentId}: ${stat.entityCount} 实体, ${stat.relationCount} 关系`)
}
```

### 6.5 增量构建

当有新文档加入时，可以增量更新知识图谱 — 自动去重，已有实体不会重复添加：

```typescript
const newDocuments = [
  { id: 'doc-004', content: 'ABC科技在2024年推出了新产品"智析 Lite"，面向中小企业。' },
]

const incrementalReport = await builder.buildFromDocuments(newDocuments)

console.log(`新增实体: ${incrementalReport.entityCount}`)
console.log(`新增关系: ${incrementalReport.relationCount}`)
```
