# 文档处理模块

> 本文档描述文档处理模块的设计理念和模块架构。具体 API 签名和使用方式请参考对应源码文件中的 JSDoc 注释。
>
> 文档处理模块涵盖文档加载、切块策略、清洗去重、元数据抽取、文档增强五大子模块。

---

## 1. 文档加载器 (DocumentLoader)

**概念：** 文档加载器负责将各种格式和来源的原始数据统一转化为 `Document` 对象。它是 RAG Pipeline 的入口，决定了系统能处理哪些数据源。

所有加载器实现 `DocumentLoader` 接口（`load(source: string | Buffer): Promise<Document[]>`），并继承 `BaseLoader` 共享 ID 生成等通用逻辑。

> 源码详见：`packages/document/src/loader/`

### 1.1 TextLoader — 纯文本加载器

**用途：** 加载 `.txt` 纯文本文件，最简单的加载器实现。

> 源码详见：`packages/document/src/loader/text-loader.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `encoding` | `BufferEncoding` | `'utf-8'` | 文件编码 |

**使用示例：**

```ts
import { TextLoader } from '@rag-sdk/document'

const loader = new TextLoader()
const docs = await loader.load('./data/report.txt')
// docs[0].content => 文件完整文本内容
```

### 1.2 MarkdownLoader — Markdown 加载器

**用途：** 加载 Markdown 文件，保留标题层级结构。可选择将整个文件作为单个文档，或按指定标题级别拆分为多个文档。

> 源码详见：`packages/document/src/loader/markdown-loader.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `splitByHeading` | `boolean` | `false` | 是否按标题拆分为多个 Document |
| `headingLevel` | `1 \| 2 \| 3` | `1` | 拆分依据的标题级别 |

**使用示例：**

```ts
import { MarkdownLoader } from '@rag-sdk/document'

// 整体加载
const loader = new MarkdownLoader()
const docs = await loader.load('./guide.md')

// 按 h2 拆分：每个二级标题章节成为一个独立 Document
const sectionLoader = new MarkdownLoader({ splitByHeading: true, headingLevel: 2 })
const sections = await sectionLoader.load('./guide.md')
```

### 1.3 PDFLoader — PDF 加载器

**用途：** 加载 PDF 文件，支持按页拆分。依赖 `pdf-parse` 库进行 PDF 解析（peer dependency，按需安装）。

> 源码详见：`packages/document/src/loader/pdf-loader.ts`

**外部依赖：** `pdf-parse`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `splitByPage` | `boolean` | `true` | 是否按页拆分，每页一个 Document |

**使用示例：**

```ts
import { PDFLoader } from '@rag-sdk/document'

const loader = new PDFLoader({ splitByPage: true })
const pages = await loader.load('./paper.pdf')
// pages[0].metadata.pageNumber => 1
// pages[0].content => 第一页的文本内容
```

### 1.4 JSONLoader — JSON 加载器

**用途：** 加载 JSON 文件，支持通过路径表达式提取嵌套字段。适用于结构化数据（API 响应、配置文件等）。

> 源码详见：`packages/document/src/loader/json-loader.ts`

| 参数 | 类型 | 说明 |
|------|------|------|
| `contentPath` | `string` | 提取内容的字段路径（如 `"data.items"`） |
| `metadataPaths` | `string[]` | 提取为元数据的字段路径列表 |

**使用示例：**

```ts
import { JSONLoader } from '@rag-sdk/document'

// 加载 API 响应，提取 data.articles 作为内容
const loader = new JSONLoader({
  contentPath: 'data.articles',
  metadataPaths: ['data.totalCount', 'data.lastUpdated'],
})
const docs = await loader.load('./api-response.json')
// 每篇文章生成一个 Document
```

### 1.5 CSVLoader — CSV 加载器

**用途：** 加载 CSV 文件，每行生成一个 Document。适用于表格型数据（产品目录、FAQ 列表等）。

> 源码详见：`packages/document/src/loader/csv-loader.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `delimiter` | `string` | `','` | 字段分隔符 |
| `contentColumns` | `string[]` | `[]` | 作为内容的列名，空则合并所有列 |
| `headerRow` | `boolean` | `true` | 首行是否为表头 |

**使用示例：**

```ts
import { CSVLoader } from '@rag-sdk/document'

const loader = new CSVLoader({ contentColumns: ['question', 'answer'] })
const docs = await loader.load('./faq.csv')
// 每行生成一个 Document，content 为 question + answer
```

### 1.6 WebLoader — 网页加载器

**用途：** 从 URL 加载网页内容，自动提取正文并去除导航栏、广告等非内容元素。依赖 `cheerio` 进行 HTML 解析（peer dependency，按需安装）。

> 源码详见：`packages/document/src/loader/web-loader.ts`

**外部依赖：** `cheerio`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `selector` | `string` | `'body'` | 提取正文的 CSS 选择器 |
| `includeImageAlt` | `boolean` | `false` | 是否保留图片 alt 文本 |
| `timeout` | `number` | `30000` | 请求超时（毫秒） |

**使用示例：**

```ts
import { WebLoader } from '@rag-sdk/document'

const loader = new WebLoader({ selector: 'article', includeImageAlt: true })
const docs = await loader.load('https://example.com/blog/post')
// docs[0].metadata.title => 文章标题
// docs[0].content => 文章正文文本
```

## 2. 切块策略 (Chunker)

**概念：** 切块策略决定如何将长文档拆分为适合检索和生成的小文本块。切块质量直接影响检索的精确度和生成答案的上下文完整性——块太大则检索噪音多，块太小则上下文断裂。

所有切块器实现 `Chunker` 接口（`chunk(document: Document, options?: ChunkOptions): Chunk[]`）。

> 源码详见：`packages/document/src/chunking/`

### 2.1 FixedSizeChunker — 固定大小切块

**概念：** 按固定的字符数切分文档，相邻块之间可设置重叠区域以保持上下文连续性。这是最基础、最快速的切块策略，适合内容均质性较高的文档。

> 源码详见：`packages/document/src/chunking/fixed-size.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `chunkSize` | `number` | `500` | 每块的目标字符数 |
| `overlap` | `number` | `50` | 相邻块的重叠字符数 |
| `separator` | `string` | `'\n'` | 优先断开的分隔符 |

**使用示例：**

```ts
import { FixedSizeChunker } from '@rag-sdk/document'

const chunker = new FixedSizeChunker({ chunkSize: 1000, overlap: 100, separator: '\n\n' })
const chunks = chunker.chunk(document)
// 每个 chunk 约 1000 字符，相邻块有 100 字符重叠
```

---

### 2.2 RecursiveChunker — 递归切块

**概念：** 先用大块切分，再递归地将大块切分为更小的块，形成层级结构。维护父子关系（`parentId` / `children`），直接支持 Small-to-Big 检索策略——先检索小粒度 chunk 精准匹配，再回溯父 chunk 获取完整上下文。

> 源码详见：`packages/document/src/chunking/recursive.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `chunkSize` | `number` | `500` | 子块的目标字符数 |
| `overlap` | `number` | `50` | 相邻块的重叠字符数 |
| `separators` | `string[]` | `['\n\n', '\n', '。', '.', ' ']` | 分隔符优先级列表 |

**使用示例：**

```ts
import { RecursiveChunker } from '@rag-sdk/document'

const chunker = new RecursiveChunker({
  chunkSize: 300,
  overlap: 30,
  separators: ['\n\n', '\n', '。', ' '],
})

const chunks = chunker.chunk(document)
// 父 chunk：chunks.filter(c => c.metadata.level === 0)
// 子 chunk：chunks.filter(c => c.metadata.level === 1)
// Small-to-Big：检索到子 chunk 后，通过 parentId 找到父 chunk
```

---

### 2.3 SemanticChunker — 语义切块

**概念：** 通过计算相邻句子的 Embedding 相似度，在语义断裂处（相似度低于阈值）切分。保证每个 chunk 在语义上自洽，适合内容跨度大、主题多变的长文档。需要 `EmbeddingProvider` 提供向量化能力。

> 源码详见：`packages/document/src/chunking/semantic.ts`

**外部依赖：** `EmbeddingProvider`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `similarityThreshold` | `number` | `0.5` | 相邻句子余弦相似度低于此值时断开 |
| `minChunkSize` | `number` | `50` | 最小 chunk 字符数，小于此值合并到相邻块 |
| `maxChunkSize` | `number` | `1000` | 最大 chunk 字符数，超过此值强制拆分 |

**使用示例：**

```ts
import { SemanticChunker } from '@rag-sdk/document'

const chunker = new SemanticChunker(embeddingProvider, {
  similarityThreshold: 0.6,
  minChunkSize: 100,
  maxChunkSize: 800,
})

const chunks = await chunker.chunkAsync(document)
// 每个 chunk 在语义上自洽，主题一致
```

---

### 2.4 MarkdownChunker — Markdown 结构切块

**概念：** 按 Markdown 标题层级（h1-h6）智能切块，保留文档的层级结构。自动在 `contextHeader` 字段中记录所属章节信息，生成的 chunk 自带上下文归属。

> 源码详见：`packages/document/src/chunking/markdown.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `headingLevel` | `number` | `2` | 以此级别标题作为切分依据 |

**使用示例：**

```ts
import { MarkdownChunker } from '@rag-sdk/document'

const chunker = new MarkdownChunker({ headingLevel: 2 })
const chunks = chunker.chunk(document)
// 每个二级标题章节成为一个独立 chunk
// chunks[0].contextHeader 包含所在章节路径
```

---

### 2.5 ContextualHeaderChunker — 上下文头切块

**概念：** 在每个 chunk 前自动添加上下文头（Contextual Chunk Header），包含文档标题、章节信息和 LLM 生成的上下文摘要。解决独立 chunk 缺少上下文导致检索和生成质量下降的问题——即使 chunk 被单独检索到，LLM 也能通过 Header 理解其所属位置和上下文。

> 源码详见：`packages/document/src/chunking/contextual-header.ts`

**外部依赖：** `LLMProvider`（生成上下文摘要）、内部 `Chunker`（实际切块）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `headerTemplate` | `string` | 内置默认 | Header 模板，支持 `{title}` `{section}` `{summary}` |
| `includeParentContext` | `boolean` | `true` | 生成摘要时是否包含文档级上下文 |

**使用示例：**

```ts
import { FixedSizeChunker, ContextualHeaderChunker } from '@rag-sdk/document'

const baseChunker = new FixedSizeChunker({ chunkSize: 500 })
const headerChunker = new ContextualHeaderChunker(llmProvider, baseChunker, {
  headerTemplate: '## {title} > {section}\n> {summary}\n\n',
})

// 1. 先切块
const chunks = headerChunker.chunk(document)
// 2. 再异步添加上下文头
const enhancedChunks = await headerChunker.addHeaders(document, chunks)
// enhancedChunks[0].contextHeader 包含章节信息和摘要
```

## 3. 去重与清洗

### 3.1 DocumentCleaner — 文档清洗

**概念：** 对文档进行预处理，去除噪音内容（HTML 标签、多余空白、页眉页脚、特殊字符），统一编码格式。清洗后的文档内容更干净，切块和检索的质量更高。

> 源码详见：`packages/document/src/cleaner.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `removeHtml` | `boolean` | `true` | 去除 HTML 标签和实体 |
| `removeExtraWhitespace` | `boolean` | `true` | 合并连续空格和空行 |
| `removeHeaderFooter` | `boolean` | `false` | 去除重复出现的页眉页脚 |
| `removeSpecialChars` | `boolean` | `false` | 去除非常规特殊字符 |
| `normalizeEncoding` | `boolean` | `true` | 统一为 UTF-8 |

**使用示例：**

```ts
import { DocumentCleaner } from '@rag-sdk/document'

const cleaner = new DocumentCleaner({
  removeHtml: true,
  removeHeaderFooter: true,
  removeSpecialChars: false,
})

const cleanedDoc = cleaner.clean(rawDocument)
// cleanedDoc.metadata.cleaned => true
```

---

### 3.2 DocumentDeduplicator — 文档去重

**概念：** 去除重复或高度相似的文档，避免冗余数据污染索引。提供两种去重模式：
- **Hash 模式（精确去重）**：基于内容 SHA-256 哈希，速度快、零误判
- **Embedding 模式（模糊去重）**：基于向量相似度，能捕获语义相同但表述不同的文档

> 源码详见：`packages/document/src/deduplicator.ts`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `mode` | `'hash' \| 'embedding' \| 'both'` | `'hash'` | 去重模式 |
| `similarityThreshold` | `number` | `0.95` | Embedding 模式下判定重复的相似度阈值 |

**使用示例：**

```ts
import { DocumentDeduplicator } from '@rag-sdk/document'

// 精确去重（快速）
const hashDedup = new DocumentDeduplicator()
const unique1 = await hashDedup.deduplicate(docs)

// 模糊去重（需要 Embedding，能捕获语义重复）
const embeddingDedup = new DocumentDeduplicator(embeddingProvider, {
  mode: 'both',
  similarityThreshold: 0.92,
})
const unique2 = await embeddingDedup.deduplicate(docs)
```

## 4. 元数据抽取 (MetadataExtractor)

**概念：** 自动为文档补充结构化元数据。基础元数据（标题、语言、字数）通过规则提取，高级元数据（主题分类、关键词、摘要）通过 LLM 提取。丰富的元数据支持 metadata 过滤检索和结果展示。

> 源码详见：`packages/document/src/metadata-extractor.ts`

**外部依赖：** `LLMProvider`（可选，用于高级元数据提取）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `useLLM` | `boolean` | `false` | 是否使用 LLM 提取高级元数据 |
| `categories` | `string[]` | 内置默认 | 主题分类候选列表 |
| `maxKeywords` | `number` | `5` | 最大关键词数量 |

**使用示例：**

```ts
import { MetadataExtractor } from '@rag-sdk/document'

// 仅规则提取（快速、零成本）
const extractor = new MetadataExtractor()
const doc1 = await extractor.extract(document)
// doc1.metadata.language => 'zh'
// doc1.metadata.wordCount => 3200

// 规则 + LLM 提取（更丰富）
const llmExtractor = new MetadataExtractor(llmProvider)
const doc2 = await llmExtractor.extract(document, {
  useLLM: true,
  categories: ['前端', '后端', '运维', '产品'],
  maxKeywords: 8,
})
// doc2.metadata.topic => '前端'
// doc2.metadata.keywords => ['React', 'TypeScript', ...]
// doc2.metadata.summary => '本文介绍了...'
```

## 5. 文档增强 (DocumentAugmenter)

**概念：** 利用 LLM 为文档生成附加内容（摘要、关键词、QA 对），增强文档的可检索性和信息密度。

QA 对增强特别有效——为文档生成可能的提问和回答，使用户的自然语言问题能直接匹配到预生成的 QA 对，显著提升检索命中率。

> 源码详见：`packages/document/src/augmenter.ts`

**外部依赖：** `LLMProvider`

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `generateSummary` | `boolean` | `true` | 是否生成摘要 |
| `generateKeywords` | `boolean` | `true` | 是否生成关键词列表 |
| `generateQA` | `boolean` | `false` | 是否生成 QA 对（成本较高） |
| `qaPairCount` | `number` | `3` | 生成 QA 对的数量 |

**使用示例：**

```ts
import { DocumentAugmenter } from '@rag-sdk/document'

const augmenter = new DocumentAugmenter(llmProvider)

// 基础增强：摘要 + 关键词
const doc1 = await augmenter.augment(document)

// 完整增强：摘要 + 关键词 + QA 对
const doc2 = await augmenter.augment(document, {
  generateSummary: true,
  generateKeywords: true,
  generateQA: true,
  qaPairCount: 5,
})
// doc2.metadata.qaPairs => [{ question: '...', answer: '...' }, ...]
```

## 6. 增量更新 (IndexManager)

**概念：** 维护文档内容 Hash 记录，在每次摄入时检测文档变更（新增、修改、删除），只处理变化的文档。避免全量重建索引的高昂成本，支持 RAG 系统的持续运维。

> 源码详见：`packages/storage/src/index-manager.ts`（位于 `@rag-sdk/storage` 包）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `hashAlgorithm` | `string` | `'sha256'` | 内容 Hash 算法 |

**关键类型：**

```typescript
interface SyncReport {
  added: number      // 新增文档数
  updated: number    // 修改文档数
  deleted: number    // 删除文档数
  unchanged: number  // 未变化文档数
}
```

**使用示例：**

```ts
import { IndexManager } from '@rag-sdk/storage'

const indexManager = new IndexManager(vectorStore, chunker, embeddingProvider)

// 首次摄入
const report1 = await indexManager.sync(allDocuments)
// report1 => { added: 50, updated: 0, deleted: 0, unchanged: 0 }

// 增量摄入：5 篇新增、3 篇修改、2 篇删除
const report2 = await indexManager.sync(updatedDocuments)
// report2 => { added: 5, updated: 3, deleted: 2, unchanged: 45 }

// 持久化 Hash 记录
const snapshot = indexManager.getHashSnapshot()
await db.save('index-hashes', snapshot)

// 恢复 Hash 记录
const saved = await db.load('index-hashes')
indexManager.restoreHashRecords(saved)
```

## 子模块依赖关系图

```
文档处理流程：

DocumentLoader（加载）→ 6 种格式支持
    │
    ▼
DocumentCleaner（清洗）→ 去噪、规范化
    │
    ▼
DocumentDeduplicator（去重）→ Hash / Embedding 两种模式
    │
    ▼
MetadataExtractor（元数据抽取）←── 可选 LLMProvider
    │
    ▼
DocumentAugmenter（文档增强）←── LLMProvider（摘要/关键词/QA对）
    │
    ▼
Chunker（切块）→ 5 种策略：
    ├── FixedSizeChunker          基础固定大小
    ├── RecursiveChunker          递归层级（支持 Small-to-Big）
    ├── SemanticChunker       ←── EmbeddingProvider
    ├── MarkdownChunker           按标题结构切分
    └── ContextualHeaderChunker ←── LLMProvider + 内部 Chunker
    │
    ▼
IndexManager（增量同步）←── VectorStore + Chunker + EmbeddingProvider
    │
    ▼
VectorStore（写入索引）
```
