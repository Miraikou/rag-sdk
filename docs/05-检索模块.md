# 检索模块

检索模块是 RAG 系统的核心环节，负责根据用户查询从知识库中找到最相关的内容。本模块分为三个子模块：**查询变换**、**搜索策略**、**后处理**。

---

## 一、查询变换 (Query Transformation)

查询变换的目标是在检索之前对用户的原始查询进行预处理和优化，提升检索质量。

### 1. QueryRewriter（查询重写）

#### 概念说明

将用户模糊、口语化的问题改写成更精准、更适合检索的 query。用户的提问往往包含口语化表达、指代不清、关键词缺失等问题，直接用于检索效果较差。

#### 解决的问题

- 用户输入过于模糊（如"这个东西怎么用"）
- 缺少关键术语和上下文
- 口语化表达与文档的书面化表达不匹配

#### TypeScript 类定义

```typescript
interface QueryRewriterOptions {
  /** 自定义重写提示词 */
  rewritePrompt?: string;
}

class QueryRewriter {
  private llmProvider: LLMProvider;
  private options: QueryRewriterOptions;

  constructor(llmProvider: LLMProvider, options?: QueryRewriterOptions) {
    this.llmProvider = llmProvider;
    this.options = options ?? {};
  }

  /**
   * 将模糊查询改写为精准的检索 query
   * @param query - 用户原始查询
   * @returns 改写后的查询
   */
  async transform(query: string): Promise<string> {
    const prompt = this.options.rewritePrompt ?? this.getDefaultPrompt();
    const rewritten = await this.llmProvider.chat([
      { role: "system", content: prompt },
      { role: "user", content: query },
    ]);
    return rewritten.content.trim();
  }

  private getDefaultPrompt(): string {
    return `你是一个查询改写助手。请将用户的模糊问题改写为更适合检索的精准查询。
要求：
1. 保留原始意图
2. 补充关键术语
3. 去除口语化表达
4. 只输出改写后的查询，不要解释`;
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `rewritePrompt` | `string` | 内置默认提示词 | 自定义重写提示词模板 |

#### 使用示例

```typescript
const rewriter = new QueryRewriter(llmProvider);

// 基础重写
const rewritten = await rewriter.transform("这个东西怎么用");
// 输出: "XX产品 使用指南 操作步骤"

// 使用自定义提示词
const customRewriter = new QueryRewriter(llmProvider, {
  rewritePrompt: `你是技术文档检索助手。
将用户问题改写为包含产品名、功能模块、操作类型的精准查询。
只输出改写结果。`,
});
const result = await customRewriter.transform("怎么导出数据");
// 输出: "数据分析模块 导出功能 CSV Excel 操作指南"
```

### 2. MultiQueryTransformer（多查询变换）

#### 概念说明

将一个问题从多个不同角度改写，生成多个 query 同时检索，然后合并结果。单次检索可能因 query 表述方式不同而遗漏相关内容，多查询可以显著提升召回率。

#### 解决的问题

- 单一 query 可能遗漏不同表述方式的相关内容
- 某些内容用 A 表述能搜到，用 B 表述搜不到
- 提升整体召回率，减少信息遗漏

#### TypeScript 类定义

```typescript
interface MultiQueryTransformerOptions {
  /** 生成的查询数量，范围 3-5 */
  numQueries?: number;
  /** 生成温度，控制多样性 */
  temperature?: number;
}

class MultiQueryTransformer {
  private llmProvider: LLMProvider;
  private options: Required<MultiQueryTransformerOptions>;

  constructor(llmProvider: LLMProvider, options?: MultiQueryTransformerOptions) {
    this.llmProvider = llmProvider;
    this.options = {
      numQueries: options?.numQueries ?? 3,
      temperature: options?.temperature ?? 0.7,
    };
  }

  /**
   * 从多个角度改写查询，生成多个 query
   * @param query - 用户原始查询
   * @returns 多个改写后的查询数组
   */
  async transform(query: string): Promise<string[]> {
    const response = await this.llmProvider.chat(
      [
        {
          role: "system",
          content: `你是一个查询改写助手。请从 ${this.options.numQueries} 个不同角度改写用户的问题。
每个改写应保持原始意图，但使用不同的表述方式和关键词。
每行输出一个改写结果，不要编号和解释。`,
        },
        { role: "user", content: query },
      ],
      { temperature: this.options.temperature }
    );

    return response.content
      .trim()
      .split("\n")
      .filter((line) => line.trim().length > 0);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `numQueries` | `number` | `3` | 生成的查询数量，范围 3-5 |
| `temperature` | `number` | `0.7` | 生成温度，越高结果越多样 |

#### 使用示例

```typescript
const multiQuery = new MultiQueryTransformer(llmProvider, {
  numQueries: 4,
  temperature: 0.8,
});

const queries = await multiQuery.transform("如何提升用户留存");
// 输出:
// [
//   "提升用户留存率的方法和最佳实践",
//   "降低用户流失率的策略与手段",
//   "增加用户活跃度和粘性的运营方案",
//   "用户生命周期管理中的留存优化技巧"
// ]

// 用多个 query 分别检索，合并结果
const allResults: SearchResult[] = [];
for (const q of queries) {
  const results = await vectorStore.search(q, { topK: 5 });
  allResults.push(...results);
}
```

### 3. QueryDecomposer（查询拆解）

#### 概念说明

将复杂问题拆分成多个独立的子问题，分别检索后综合回答。与 MultiQueryTransformer 不同，QueryDecomposer 不是从不同角度改写同一个问题，而是把一个复合问题拆成多个真正独立的子问题。

#### 解决的问题

- 复杂问题涉及多个维度，单一 query 难以覆盖
- 拆分后的子问题更聚焦，检索更精准
- 每个子问题可以独立检索和验证

#### TypeScript 类定义

```typescript
interface QueryDecomposerOptions {
  /** 最大子问题数量 */
  maxSubQueries?: number;
}

interface DecompositionResult {
  /** 拆解后的子问题列表 */
  subQueries: string[];
  /** 原始问题 */
  originalQuery: string;
}

class QueryDecomposer {
  private llmProvider: LLMProvider;
  private options: Required<QueryDecomposerOptions>;

  constructor(llmProvider: LLMProvider, options?: QueryDecomposerOptions) {
    this.llmProvider = llmProvider;
    this.options = {
      maxSubQueries: options?.maxSubQueries ?? 5,
    };
  }

  /**
   * 将复杂问题拆解为多个独立子问题
   * @param query - 复杂的原始查询
   * @returns 拆解后的子问题数组
   */
  async transform(query: string): Promise<string[]> {
    const response = await this.llmProvider.chat([
      {
        role: "system",
        content: `你是一个问题拆解助手。请将用户的复杂问题拆解为最多 ${this.options.maxSubQueries} 个独立的子问题。
每个子问题应该：
1. 可以独立检索和回答
2. 覆盖原始问题的一个方面
3. 表述清晰、具体
每行输出一个子问题，不要编号和解释。`,
      },
      { role: "user", content: query },
    ]);

    return response.content
      .trim()
      .split("\n")
      .filter((line) => line.trim().length > 0);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `maxSubQueries` | `number` | `5` | 最大子问题数量 |

#### 使用示例

```typescript
const decomposer = new QueryDecomposer(llmProvider, { maxSubQueries: 4 });

const subQueries = await decomposer.transform(
  "对比 React 和 Vue 的生态系统、学习曲线、性能和适用场景"
);
// 输出:
// [
//   "React 生态系统包含哪些核心库和常用工具",
//   "Vue 生态系统包含哪些核心库和常用工具",
//   "React 和 Vue 的学习曲线对比",
//   "React 和 Vue 在不同规模项目中的适用场景"
// ]

// 分别检索每个子问题
const resultsPerQuery = await Promise.all(
  subQueries.map((q) => vectorStore.search(q, { topK: 3 }))
);
```

### 4. HyDETransformer（假设文档嵌入）

#### 概念说明

HyDE（Hypothetical Document Embeddings）先让 LLM 针对用户问题生成一个假设性的答案文档，然后用这个假设文档（而非原始 query）去做向量检索。

#### 解决的问题

用户查询通常是口语化的短句（如"怎么部署到生产环境"），而知识库中的文档是正式的、详细的书面表达。两者在 Embedding 空间中的距离可能较远，导致检索效果差。通过生成假设文档，弥合了口语化 query 和正式文档之间的语义鸿沟。

#### TypeScript 类定义

```typescript
interface HyDETransformerOptions {
  /** 自定义生成假设文档的提示词 */
  generatePrompt?: string;
}

class HyDETransformer {
  private llmProvider: LLMProvider;
  private options: HyDETransformerOptions;

  constructor(llmProvider: LLMProvider, options?: HyDETransformerOptions) {
    this.llmProvider = llmProvider;
    this.options = options ?? {};
  }

  /**
   * 生成假设文档用于检索
   * @param query - 用户原始查询
   * @returns 假设文档文本（用于替代原始 query 进行检索）
   */
  async transform(query: string): Promise<string> {
    const prompt = this.options.generatePrompt ?? this.getDefaultPrompt();
    const response = await this.llmProvider.chat([
      { role: "system", content: prompt },
      { role: "user", content: query },
    ]);
    return response.content.trim();
  }

  private getDefaultPrompt(): string {
    return `请针对用户的问题，撰写一段详细的专业回答。
要求：
1. 以专业文档的风格撰写
2. 尽可能详细和全面
3. 不需要完全准确，重点是覆盖可能的关键词和概念
4. 直接输出回答内容`;
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `generatePrompt` | `string` | 内置默认提示词 | 自定义生成假设文档的提示词 |

#### 使用示例

```typescript
const hyde = new HyDETransformer(llmProvider);

// 1. 生成假设文档
const hypotheticalDoc = await hyde.transform("如何优化数据库查询性能");
// 输出: "优化数据库查询性能可以从多个维度入手：
//   1. 索引优化：为高频查询字段建立合适的索引...
//   2. 查询语句优化：避免全表扫描，使用 EXPLAIN 分析...
//   3. 缓存策略：引入 Redis 等缓存层...
//   4. 分库分表：在数据量大时进行水平或垂直拆分..."

// 2. 用假设文档的 Embedding 去检索（而非原始 query）
const embedding = await embeddingProvider.embed(hypotheticalDoc);
const results = await vectorStore.searchByVector(embedding, { topK: 5 });
```

### 5. RetrievalRouter（检索路由）

#### 概念说明

根据问题的类型、内容、复杂度等信息，动态决定走哪条检索路径。不同的问题适合不同的数据源和检索方式，路由机制可以实现精准的检索策略分发。

#### 解决的问题

- 不同类型的问题需要检索不同的数据源
- 不同场景适合不同的检索方式（向量、关键词、知识图谱）
- 简单问题无需复杂的多路检索，避免资源浪费

#### TypeScript 类定义

```typescript
/** 路由决策结果 */
interface RouteDecision {
  /** 路由类型标识 */
  type: string;
  /** 选中的检索器 */
  retriever: Retriever;
  /** 传递给检索器的额外参数 */
  options?: Record<string, unknown>;
}

/** 路由规则定义 */
interface RouteRule {
  /** 规则名称 */
  name: string;
  /** 匹配条件函数 */
  match: (query: string) => boolean | Promise<boolean>;
  /** 匹配后返回的检索器 */
  retriever: Retriever;
  /** 额外参数 */
  options?: Record<string, unknown>;
}

class RetrievalRouter {
  private llmProvider: LLMProvider;
  private rules: RouteRule[];
  private defaultRetriever: Retriever;

  constructor(
    llmProvider: LLMProvider,
    rules: RouteRule[],
    defaultRetriever: Retriever
  ) {
    this.llmProvider = llmProvider;
    this.rules = rules;
    this.defaultRetriever = defaultRetriever;
  }

  /**
   * 根据查询内容决定路由
   * @param query - 用户查询
   * @returns 路由决策
   */
  async route(query: string): Promise<RouteDecision> {
    // 按优先级依次匹配规则
    for (const rule of this.rules) {
      const matched = await rule.match(query);
      if (matched) {
        return {
          type: rule.name,
          retriever: rule.retriever,
          options: rule.options,
        };
      }
    }

    // 无匹配规则时使用默认检索器
    return {
      type: "default",
      retriever: this.defaultRetriever,
    };
  }
}
```

#### 路由方式

**按数据源路由**：根据问题内容判断应检索哪个数据源（产品文档、财务数据、代码文档等）。

**按检索方式路由**：根据问题特征选择最合适的检索方式（向量检索、关键词检索、知识图谱查询等）。

**按复杂度路由**：简单问题走单次检索，复杂问题走多路检索融合。

#### 使用示例

```typescript
// 定义路由规则
const rules: RouteRule[] = [
  // 按数据源路由：财务相关问题 → 财务数据库
  {
    name: "finance",
    match: (query) =>
      /财报|营收|利润|成本|预算|财务/.test(query),
    retriever: financeRetriever,
    options: { topK: 10 },
  },
  // 按数据源路由：产品功能问题 → 产品文档库
  {
    name: "product-docs",
    match: (query) =>
      /功能|操作|设置|配置|怎么用/.test(query),
    retriever: productDocsRetriever,
    options: { topK: 5 },
  },
  // 按检索方式路由：精确查找 → 关键词检索
  {
    name: "keyword-search",
    match: (query) =>
      /错误码|API名称|函数名|报错信息/.test(query),
    retriever: keywordRetriever,
  },
  // 按复杂度路由：复杂问题 → 多路融合检索
  {
    name: "complex-fusion",
    match: async (query) => {
      // 用 LLM 判断问题复杂度
      const result = await llmProvider.chat([
        { role: "user", content: `判断以下问题的复杂度（简单/复杂）：${query}` },
      ]);
      return result.content.includes("复杂");
    },
    retriever: fusionRetriever,
    options: { vectorWeight: 0.6, keywordWeight: 0.4 },
  },
];

const router = new RetrievalRouter(llmProvider, rules, defaultVectorRetriever);

// 路由到财务检索
const decision1 = await router.route("去年第三季度的营收是多少");
// → { type: "finance", retriever: financeRetriever, options: { topK: 10 } }

// 路由到产品文档
const decision2 = await router.route("怎么配置消息通知功能");
// → { type: "product-docs", retriever: productDocsRetriever, options: { topK: 5 } }

// 执行检索
const results = await decision1.retriever.retrieve(query, decision1.options);
```

## 二、搜索策略 (Search Strategies)

搜索策略定义了从知识库中查找相关内容的具体方式。不同策略有不同的优势和适用场景。

### 1. VectorSearch（向量检索）

#### 概念说明

将查询文本通过 Embedding 模型转换为向量，然后在向量数据库中计算余弦相似度，找到语义最相近的文档片段。这是 RAG 系统中最基础的检索方式。

#### 解决的问题

- 语义级别的匹配，能理解同义词、近义表达
- 不依赖精确的关键词匹配
- 适合模糊查询和概念性查询

#### TypeScript 类定义

```typescript
interface VectorSearchOptions {
  /** 返回结果数量 */
  topK?: number;
  /** 最低相似度阈值 */
  minScore?: number;
  /** 元数据过滤条件 */
  filter?: Record<string, unknown>;
}

interface SearchResult {
  /** 文档片段内容 */
  content: string;
  /** 相似度分数 */
  score: number;
  /** 元数据 */
  metadata: Record<string, unknown>;
  /** 唯一标识 */
  id: string;
}

class VectorSearch {
  private embeddingProvider: EmbeddingProvider;
  private vectorStore: VectorStore;

  constructor(embeddingProvider: EmbeddingProvider, vectorStore: VectorStore) {
    this.embeddingProvider = embeddingProvider;
    this.vectorStore = vectorStore;
  }

  /**
   * 使用向量相似度进行检索
   * @param query - 用户查询
   * @param options - 检索选项
   * @returns 检索结果列表
   */
  async retrieve(
    query: string,
    options?: VectorSearchOptions
  ): Promise<SearchResult[]> {
    const { topK = 5, minScore = 0, filter } = options ?? {};

    // 1. 将 query 转换为向量
    const queryEmbedding = await this.embeddingProvider.embed(query);

    // 2. 在向量数据库中检索
    const results = await this.vectorStore.search(queryEmbedding, {
      topK,
      filter,
    });

    // 3. 过滤低于阈值的结果
    return results.filter((result) => result.score >= minScore);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `topK` | `number` | `5` | 返回结果数量 |
| `minScore` | `number` | `0` | 最低相似度阈值 |
| `filter` | `Record<string, unknown>` | `undefined` | 元数据过滤条件 |

#### 使用示例

```typescript
const vectorSearch = new VectorSearch(embeddingProvider, vectorStore);

// 基础检索
const results = await vectorSearch.retrieve("如何配置用户权限", {
  topK: 5,
  minScore: 0.7,
});

// 带元数据过滤的检索
const filteredResults = await vectorSearch.retrieve("部署指南", {
  topK: 10,
  filter: { category: "运维文档", version: "v2.0" },
});
```

### 2. KeywordSearch（BM25 关键词检索）

#### 概念说明

基于 BM25 算法的关键词检索，通过词频（TF）和逆文档频率（IDF）计算查询与文档的相关性分数。这是一种经典的稀疏检索方法。

#### 解决的问题

- 专有名词、代码片段、错误码等精确匹配场景
- 向量检索对精确关键词匹配不够敏感
- 不依赖外部 Embedding 模型，可独立运行

#### TypeScript 类定义

```typescript
interface KeywordSearchOptions {
  /** 返回结果数量 */
  topK?: number;
  /** BM25 参数 k1（词频饱和参数） */
  k1?: number;
  /** BM25 参数 b（长度归一化参数） */
  b?: number;
}

interface BM25Document {
  id: string;
  content: string;
  terms: string[];
}

class KeywordSearch {
  private documents: BM25Document[];
  private avgDocLength: number;
  private docFreq: Map<string, number>;
  private options: Required<Omit<KeywordSearchOptions, "topK">>;

  constructor(documents: BM25Document[], options?: KeywordSearchOptions) {
    this.documents = documents;
    this.options = {
      k1: options?.k1 ?? 1.5,
      b: options?.b ?? 0.75,
    };

    // 预处理：计算平均文档长度和文档频率
    this.avgDocLength =
      documents.reduce((sum, doc) => sum + doc.terms.length, 0) /
      documents.length;
    this.docFreq = this.buildDocFrequency();
  }

  /**
   * 使用 BM25 算法进行关键词检索
   * @param query - 用户查询
   * @param options - 检索选项
   * @returns 按 BM25 分数排序的检索结果
   */
  async retrieve(
    query: string,
    options?: KeywordSearchOptions
  ): Promise<SearchResult[]> {
    const topK = options?.topK ?? 5;
    const queryTerms = this.tokenize(query);

    const scored = this.documents.map((doc) => ({
      id: doc.id,
      content: doc.content,
      score: this.calculateBM25Score(doc, queryTerms),
      metadata: {},
    }));

    return scored
      .sort((a, b) => b.score - a.score)
      .slice(0, topK)
      .filter((r) => r.score > 0);
  }

  private calculateBM25Score(doc: BM25Document, queryTerms: string[]): number {
    const { k1, b } = this.options;
    let score = 0;

    for (const term of queryTerms) {
      const tf = doc.terms.filter((t) => t === term).length;
      const df = this.docFreq.get(term) ?? 0;
      const idf = Math.log(
        (this.documents.length - df + 0.5) / (df + 0.5) + 1
      );
      const tfNorm =
        (tf * (k1 + 1)) /
        (tf + k1 * (1 - b + b * (doc.terms.length / this.avgDocLength)));
      score += idf * tfNorm;
    }

    return score;
  }

  private buildDocFrequency(): Map<string, number> {
    const freq = new Map<string, number>();
    for (const doc of this.documents) {
      const uniqueTerms = new Set(doc.terms);
      for (const term of uniqueTerms) {
        freq.set(term, (freq.get(term) ?? 0) + 1);
      }
    }
    return freq;
  }

  private tokenize(text: string): string[] {
    // 简单分词实现，生产环境应使用专业分词器
    return text
      .toLowerCase()
      .replace(/[^\w一-鿿]/g, " ")
      .split(/\s+/)
      .filter((t) => t.length > 0);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `topK` | `number` | `5` | 返回结果数量 |
| `k1` | `number` | `1.5` | BM25 词频饱和参数 |
| `b` | `number` | `0.75` | BM25 长度归一化参数 |

#### 使用示例

```typescript

// 精确匹配检索

  topK: 5,
});
// BM25 对错误信息、代码片段等精确匹配效果很好

// 精确匹配到包含这些 Hook 名称的文档
```

### 3. FusionRetriever（融合检索）

#### 概念说明

同时使用向量检索和关键词检索，将两者的结果按权重合并。结合了向量检索的语义理解能力和关键词检索的精确匹配能力。

#### 解决的问题

- 单一检索方式各有盲区：向量检索可能漏掉精确关键词匹配，关键词检索缺乏语义理解
- 融合两种方式可以取长补短，提升整体检索质量

#### TypeScript 类定义

```typescript
interface FusionRetrieverOptions {
  /** 向量检索权重，范围 0-1 */
  vectorWeight?: number;
  /** 关键词检索权重，范围 0-1 */
  keywordWeight?: number;
  /** 返回结果数量 */
  topK?: number;
}

class FusionRetriever {
  private vectorSearch: VectorSearch;
  private keywordSearch: KeywordSearch;
  private options: Required<Omit<FusionRetrieverOptions, "topK">>;

  constructor(
    vectorSearch: VectorSearch,
    keywordSearch: KeywordSearch,
    options?: FusionRetrieverOptions
  ) {
    this.vectorSearch = vectorSearch;
    this.keywordSearch = keywordSearch;
    this.options = {
      vectorWeight: options?.vectorWeight ?? 0.5,
      keywordWeight: options?.keywordWeight ?? 0.5,
    };
  }

  /**
   * 融合向量和关键词检索
   * @param query - 用户查询
   * @param options - 检索选项
   * @returns 融合后的检索结果
   */
  async retrieve(
    query: string,
    options?: FusionRetrieverOptions
  ): Promise<SearchResult[]> {
    const topK = options?.topK ?? 10;
    const vectorWeight = options?.vectorWeight ?? this.options.vectorWeight;
    const keywordWeight = options?.keywordWeight ?? this.options.keywordWeight;

    // 1. 并行执行两种检索
    const [vectorResults, keywordResults] = await Promise.all([
      this.vectorSearch.retrieve(query, { topK: topK * 2 }),
      this.keywordSearch.retrieve(query, { topK: topK * 2 }),
    ]);

    // 2. 合并结果并按加权分数排序
    const mergedMap = new Map<string, SearchResult>();

    for (const result of vectorResults) {
      mergedMap.set(result.id, {
        ...result,
        score: result.score * vectorWeight,
      });
    }

    for (const result of keywordResults) {
      const existing = mergedMap.get(result.id);
      if (existing) {
        existing.score += result.score * keywordWeight;
      } else {
        mergedMap.set(result.id, {
          ...result,
          score: result.score * keywordWeight,
        });
      }
    }

    return Array.from(mergedMap.values())
      .sort((a, b) => b.score - a.score)
      .slice(0, topK);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `vectorWeight` | `number` | `0.5` | 向量检索权重 |
| `keywordWeight` | `number` | `0.5` | 关键词检索权重 |
| `topK` | `number` | `10` | 返回结果数量 |

#### 使用示例

```typescript
const fusion = new FusionRetriever(vectorSearch, keywordSearch, {
  vectorWeight: 0.6,
  keywordWeight: 0.4,
});

// 融合检索
const results = await fusion.retrieve("React useEffect 内存泄漏", {
  topK: 10,
});
// 向量检索能理解"内存泄漏"的语义
// 关键词检索能精确匹配"React"和"useEffect"

// 偏向语义理解的场景
const semanticResults = await fusion.retrieve("如何提高系统可用性", {
  topK: 8,
  vectorWeight: 0.8,
  keywordWeight: 0.2,
});
```

### 4. RRF（Reciprocal Rank Fusion，倒数排名融合）

#### 概念说明

RRF 是一种基于排名而非分数的融合算法。核心公式为 `score = Σ 1/(k + rank)`，其中 k 是常数（通常为 60）。它不依赖各路检索的原始分数（因为不同检索方式的分数尺度不同），只看每个文档在各路结果中的排名。

#### 解决的问题

- 不同检索方式的分数尺度不同（向量余弦相似度 vs BM25 分数），无法直接加权比较
- RRF 只看排名不看分数，天然解决了分数不可比的问题
- 通常配合 FusionRetriever 使用，作为结果融合的最终步骤

#### TypeScript 类定义

```typescript
class RRF {
  private k: number;

  /**
   * @param k - 平滑常数，默认 60
   */
  constructor(k: number = 60) {
    this.k = k;
  }

  /**
   * 对多路检索结果按排名融合
   * @param results - 多路检索结果，每个元素是一路检索的结果数组
   * @returns 融合后按 RRF 分数排序的结果
   */
  fuse(results: SearchResult[][]): SearchResult[] {
    const scoreMap = new Map<string, { result: SearchResult; score: number }>();

    for (const resultList of results) {
      resultList.forEach((result, index) => {
        const rank = index + 1; // 排名从 1 开始
        const rrfScore = 1 / (this.k + rank);

        const existing = scoreMap.get(result.id);
        if (existing) {
          existing.score += rrfScore;
        } else {
          scoreMap.set(result.id, {
            result: { ...result },
            score: rrfScore,
          });
        }
      });
    }

    return Array.from(scoreMap.values())
      .sort((a, b) => b.score - a.score)
      .map(({ result, score }) => ({
        ...result,
        score,
      }));
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `k` | `number` | `60` | 平滑常数，控制排名对分数的影响程度 |

#### 使用示例

```typescript
const rrf = new RRF(60);

// 分别获取两路检索结果
const vectorResults = await vectorSearch.retrieve(query, { topK: 10 });
const keywordResults = await keywordSearch.retrieve(query, { topK: 10 });

// 使用 RRF 融合
const fused = rrf.fuse([vectorResults, keywordResults]);
// 在两个列表中排名都靠前的文档会获得更高的 RRF 分数

// 融合三路检索结果
const hydeResults = await hydeSearch.retrieve(query, { topK: 10 });
const tripleFused = rrf.fuse([vectorResults, keywordResults, hydeResults]);
```

### 5. SmallToBigRetriever（小块检索大块返回）

#### 概念说明

使用较小的文档块进行检索（更精准），但返回时扩展到包含该小块的大块（更完整的上下文）。这依赖于文档分块时建立的父子关系。

#### 解决的问题

- 小块检索精度高但上下文不完整
- 大块检索上下文完整但匹配精度低
- SmallToBig 兼顾两者：用小块精准匹配，返回大块完整上下文

#### TypeScript 类定义

```typescript
interface SmallToBigRetrieverOptions {
  /** 返回结果数量 */
  topK?: number;
}

interface ChunkRelation {
  /** 小块（子块）ID */
  childId: string;
  /** 大块（父块）ID */
  parentId: string;
}

class SmallToBigRetriever {
  private vectorSearch: VectorSearch;
  private documentStore: DocumentStore;
  private relations: Map<string, string>; // childId → parentId

  constructor(
    vectorSearch: VectorSearch,
    documentStore: DocumentStore,
    relations: ChunkRelation[]
  ) {
    this.vectorSearch = vectorSearch;
    this.documentStore = documentStore;
    this.relations = new Map(
      relations.map((r) => [r.childId, r.parentId])
    );
  }

  /**
   * 小块检索，大块返回
   * @param query - 用户查询
   * @param options - 检索选项
   * @returns 扩展后的检索结果（大块内容）
   */
  async retrieve(
    query: string,
    options?: SmallToBigRetrieverOptions
  ): Promise<SearchResult[]> {
    const topK = options?.topK ?? 5;

    // 1. 用小块进行精准检索
    const smallResults = await this.vectorSearch.retrieve(query, {
      topK: topK * 2, // 多检索一些，去重后数量会减少
    });

    // 2. 找到每个小块对应的大块
    const parentIds = new Set<string>();
    const expandedResults: SearchResult[] = [];

    for (const result of smallResults) {
      const parentId = this.relations.get(result.id);
      if (parentId && !parentIds.has(parentId)) {
        parentIds.add(parentId);

        // 3. 获取大块的完整内容
        const parentDoc = await this.documentStore.getById(parentId);
        if (parentDoc) {
          expandedResults.push({
            id: parentDoc.id,
            content: parentDoc.content,
            score: result.score,
            metadata: {
              ...parentDoc.metadata,
              matchedChildId: result.id,
              childContent: result.content,
            },
          });
        }
      }

      if (expandedResults.length >= topK) break;
    }

    return expandedResults;
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `topK` | `number` | `5` | 返回的大块结果数量 |

#### 使用示例

```typescript
// 假设已通过 RecursiveChunker 建立了父子关系
const relations: ChunkRelation[] = [
  { childId: "chunk-1-1", parentId: "chunk-1" },
  { childId: "chunk-1-2", parentId: "chunk-1" },
  { childId: "chunk-2-1", parentId: "chunk-2" },
  // ...
];

const smallToBig = new SmallToBigRetriever(
  vectorSearch,
  documentStore,
  relations
);

const results = await smallToBig.retrieve("用户认证流程", { topK: 3 });
// 小块精准匹配到"JWT token 验证"片段
// 返回时扩展到包含完整认证流程的大块内容
```

### 6. HierarchicalRetriever（分层索引检索）

#### 概念说明

建立两层索引：摘要索引（每个文档的摘要/概述）和内容索引（文档的具体片段）。检索时先在摘要层找到相关文档，再在对应文档的内容层做精细检索。

#### 解决的问题

- 大规模文档库中，直接全量检索效率低且可能匹配到不相关文档的片段
- 分层检索先粗筛再精选，兼顾效率和精度
- 适合文档数量多、每篇文档较长的场景

#### TypeScript 类定义

```typescript
interface HierarchicalRetrieverOptions {
  /** 摘要层返回的文档数量 */
  summaryTopK?: number;
  /** 内容层每个文档返回的片段数量 */
  contentTopK?: number;
}

interface SummaryDocument {
  id: string;
  title: string;
  summary: string;
  embedding: number[];
}

interface ContentChunk {
  id: string;
  documentId: string;
  content: string;
  embedding: number[];
}

class HierarchicalRetriever {
  private embeddingProvider: EmbeddingProvider;
  private summaryIndex: VectorStore; // 摘要层索引
  private contentIndex: Map<string, VectorStore>; // 内容层索引（按文档 ID 分组）

  constructor(
    embeddingProvider: EmbeddingProvider,
    summaryIndex: VectorStore,
    contentIndex: Map<string, VectorStore>
  ) {
    this.embeddingProvider = embeddingProvider;
    this.summaryIndex = summaryIndex;
    this.contentIndex = contentIndex;
  }

  /**
   * 分层检索：先搜摘要层，再搜内容层
   * @param query - 用户查询
   * @param options - 检索选项
   * @returns 最终检索结果
   */
  async retrieve(
    query: string,
    options?: HierarchicalRetrieverOptions
  ): Promise<SearchResult[]> {
    const summaryTopK = options?.summaryTopK ?? 3;
    const contentTopK = options?.contentTopK ?? 3;

    const queryEmbedding = await this.embeddingProvider.embed(query);

    // 第一层：在摘要索引中找到相关文档
    const summaryResults = await this.summaryIndex.search(queryEmbedding, {
      topK: summaryTopK,
    });

    // 第二层：在每个相关文档的内容索引中精细检索
    const allContentResults: SearchResult[] = [];

    for (const summaryResult of summaryResults) {
      const docContentIndex = this.contentIndex.get(summaryResult.id);
      if (!docContentIndex) continue;

      const contentResults = await docContentIndex.search(queryEmbedding, {
        topK: contentTopK,
      });

      allContentResults.push(
        ...contentResults.map((r) => ({
          ...r,
          metadata: {
            ...r.metadata,
            parentDocumentId: summaryResult.id,
            parentTitle: summaryResult.metadata["title"],
          },
        }))
      );
    }

    return allContentResults
      .sort((a, b) => b.score - a.score)
      .slice(0, summaryTopK * contentTopK);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `summaryTopK` | `number` | `3` | 摘要层返回的文档数量 |
| `contentTopK` | `number` | `3` | 内容层每个文档返回的片段数量 |

#### 使用示例

```typescript
const hierarchical = new HierarchicalRetriever(
  embeddingProvider,
  summaryIndex,
  contentIndex
);

const results = await hierarchical.retrieve("微服务架构设计", {
  summaryTopK: 3,  // 先找 3 篇相关文档
  contentTopK: 2,  // 每篇文档取 2 个最相关片段
});
// 最终最多返回 3 × 2 = 6 个片段
```

## 三、后处理 (Post-Processing)

后处理是在检索完成后、送入 LLM 之前，对检索结果进行进一步优化，提升最终生成质量。

### 1. ThresholdFilter（阈值过滤）

#### 概念说明

丢弃相似度分数低于阈值的结果，确保送入 LLM 的内容都具有足够的相关性。支持固定阈值和动态阈值两种模式。

#### 解决的问题

- 检索结果中可能包含不相关的低分内容
- 低分内容会干扰 LLM 生成，引入噪声甚至导致幻觉

#### TypeScript 类定义

```typescript
interface ThresholdFilterOptions {
  /** 固定阈值，分数低于此值的结果将被过滤 */
  threshold?: number;
  /** 是否启用动态阈值（基于结果分数分布自动调整） */
  dynamic?: boolean;
  /** 动态阈值的标准差倍数 */
  stdMultiplier?: number;
}

class ThresholdFilter {
  private options: Required<ThresholdFilterOptions>;

  constructor(options?: ThresholdFilterOptions) {
    this.options = {
      threshold: options?.threshold ?? 0.5,
      dynamic: options?.dynamic ?? false,
      stdMultiplier: options?.stdMultiplier ?? 1.0,
    };
  }

  /**
   * 过滤低于阈值的结果
   * @param results - 检索结果列表
   * @param query - 用户查询（动态阈值模式下可用于上下文判断）
   * @returns 过滤后的结果列表
   */
  async process(
    results: SearchResult[],
    query: string
  ): Promise<SearchResult[]> {
    if (results.length === 0) return [];

    if (this.options.dynamic) {
      return this.applyDynamicThreshold(results);
    }

    return results.filter((r) => r.score >= this.options.threshold);
  }

  private applyDynamicThreshold(results: SearchResult[]): SearchResult[] {
    const scores = results.map((r) => r.score);
    const mean = scores.reduce((a, b) => a + b, 0) / scores.length;
    const std = Math.sqrt(
      scores.reduce((sum, s) => sum + (s - mean) ** 2, 0) / scores.length
    );

    const dynamicThreshold = mean - this.options.stdMultiplier * std;
    return results.filter((r) => r.score >= dynamicThreshold);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `threshold` | `number` | `0.5` | 固定阈值 |
| `dynamic` | `boolean` | `false` | 是否启用动态阈值 |
| `stdMultiplier` | `number` | `1.0` | 动态阈值的标准差倍数 |

#### 使用示例

```typescript
// 固定阈值
const fixedFilter = new ThresholdFilter({ threshold: 0.7 });
const filtered = await fixedFilter.process(results, query);

// 动态阈值：自动根据分数分布调整
const dynamicFilter = new ThresholdFilter({
  dynamic: true,
  stdMultiplier: 1.5,
});
const dynamicFiltered = await dynamicFilter.process(results, query);
// 如果所有结果分数都很高，动态阈值会自动提高过滤标准
// 如果结果分数普遍偏低，动态阈值会适当降低
```

### 2. Reranker（重排序）

#### 概念说明

使用 Cross-Encoder 模型对 query 和每个检索结果进行联合编码，计算更精准的相关性分数，然后重新排序。Cross-Encoder 比 Bi-Encoder（Embedding 向量检索）精度更高，但计算成本也更高，因此只用于对少量结果做重排序。

#### 解决的问题

- 向量检索（Bi-Encoder）的分数不够精准
- Cross-Encoder 能捕捉 query 和文档之间更细粒度的交互关系
- 在大量候选结果中筛选出真正最相关的 top 结果

#### TypeScript 类定义

```typescript
interface RerankerOptions {
  /** 重排序后保留的结果数量 */
  topK?: number;
  /** Reranker 模型名称 */
  model?: string;
}

interface RerankerProvider {
  rerank(query: string, documents: string[], model: string): Promise<number[]>;
}

class Reranker {
  private rerankerProvider: RerankerProvider;
  private options: Required<RerankerOptions>;

  constructor(rerankerProvider: RerankerProvider, options?: RerankerOptions) {
    this.rerankerProvider = rerankerProvider;
    this.options = {
      topK: options?.topK ?? 5,
      model: options?.model ?? "rerank-v1",
    };
  }

  /**
   * 对检索结果进行重排序
   * @param results - 初始检索结果
   * @param query - 用户查询
   * @returns 重排序后的结果
   */
  async process(
    results: SearchResult[],
    query: string
  ): Promise<SearchResult[]> {
    if (results.length === 0) return [];

    const documents = results.map((r) => r.content);

    // 调用 Reranker 模型计算新分数
    const newScores = await this.rerankerProvider.rerank(
      query,
      documents,
      this.options.model
    );

    // 用新分数替换原分数并重新排序
    const rescored = results.map((result, index) => ({
      ...result,
      score: newScores[index],
      metadata: {
        ...result.metadata,
        originalScore: result.score,
      },
    }));

    return rescored
      .sort((a, b) => b.score - a.score)
      .slice(0, this.options.topK);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `topK` | `number` | `5` | 重排序后保留的结果数量 |
| `model` | `string` | `"rerank-v1"` | Reranker 模型名称 |

#### 使用示例

```typescript
// 使用 Cohere Reranker
const reranker = new Reranker(cohereRerankerProvider, {
  topK: 5,
  model: "rerank-english-v3.0",
});

// 先用向量检索获取候选结果
const candidates = await vectorSearch.retrieve(query, { topK: 20 });

// 用 Reranker 重排序，取 top 5
const reranked = await reranker.process(candidates, query);
// Reranker 能更准确地判断哪些结果真正与 query 相关
```

### 3. ContextEnricher（上下文增强）

#### 概念说明

检索到某个文档片段后，自动带上其前后相邻的片段，提供更完整的上下文信息。

#### 解决的问题

- 检索到的 chunk 可能缺少前后文，信息不完整
- 一个段落的关键信息可能在相邻段落中有补充说明
- LLM 需要更完整的上下文才能生成准确的回答

#### TypeScript 类定义

```typescript
interface ContextEnricherOptions {
  /** 前后各扩展的 chunk 数量 */
  window?: number;
}

interface OrderedChunk {
  id: string;
  content: string;
  /** 在原始文档中的顺序索引 */
  orderIndex: number;
  /** 所属文档 ID */
  documentId: string;
}

class ContextEnricher {
  private chunkStore: ChunkStore;
  private options: Required<ContextEnricherOptions>;

  constructor(chunkStore: ChunkStore, options?: ContextEnricherOptions) {
    this.chunkStore = chunkStore;
    this.options = {
      window: options?.window ?? 1,
    };
  }

  /**
   * 为检索结果添加上下文
   * @param results - 检索结果
   * @param query - 用户查询
   * @returns 增强后的结果
   */
  async process(
    results: SearchResult[],
    query: string
  ): Promise<SearchResult[]> {
    const enriched: SearchResult[] = [];

    for (const result of results) {
      const chunk = await this.chunkStore.getById(result.id) as OrderedChunk;
      if (!chunk) {
        enriched.push(result);
        continue;
      }

      // 获取前后相邻的 chunk
      const contextChunks = await this.chunkStore.getByRange(
        chunk.documentId,
        chunk.orderIndex - this.options.window,
        chunk.orderIndex + this.options.window
      );

      // 拼接完整上下文
      const fullContent = contextChunks
        .sort((a, b) => a.orderIndex - b.orderIndex)
        .map((c) => c.content)
        .join("\n\n");

      enriched.push({
        ...result,
        content: fullContent,
        metadata: {
          ...result.metadata,
          originalContent: result.content,
          enrichedWindow: this.options.window,
        },
      });
    }

    return enriched;
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `window` | `number` | `1` | 前后各扩展的 chunk 数量 |

#### 使用示例

```typescript
const enricher = new ContextEnricher(chunkStore, { window: 2 });

const results = await vectorSearch.retrieve(query, { topK: 5 });
const enriched = await enricher.process(results, query);

// 原始结果: chunk-5
// 增强后: chunk-3 + chunk-4 + chunk-5 + chunk-6 + chunk-7
// LLM 获得了更完整的前后文上下文
```

### 4. SelectiveContext（RSC 选择性上下文）

#### 概念说明

在检索到的 chunk 中，只保留与 query 相关的句子，过滤掉不相关的句子。这是一种细粒度的上下文过滤，在句子级别操作。

#### 解决的问题

- 一个 chunk 中可能只有部分句子与 query 相关
- 不相关的句子会占用上下文窗口、干扰 LLM 生成
- 精简约上下文可以提升生成质量并降低成本

#### TypeScript 类定义

```typescript
interface SelectiveContextOptions {
  /** 句子相关性阈值 */
  threshold?: number;
}

class SelectiveContext {
  private embeddingProvider: EmbeddingProvider;
  private options: Required<SelectiveContextOptions>;

  constructor(
    embeddingProvider: EmbeddingProvider,
    options?: SelectiveContextOptions
  ) {
    this.embeddingProvider = embeddingProvider;
    this.options = {
      threshold: options?.threshold ?? 0.5,
    };
  }

  /**
   * 选择性过滤：只保留与 query 相关的句子
   * @param results - 检索结果
   * @param query - 用户查询
   * @returns 过滤后的结果
   */
  async process(
    results: SearchResult[],
    query: string
  ): Promise<SearchResult[]> {
    const queryEmbedding = await this.embeddingProvider.embed(query);

    const filtered = await Promise.all(
      results.map(async (result) => {
        const sentences = this.splitSentences(result.content);

        // 计算每个句子与 query 的相似度
        const sentenceScores = await Promise.all(
          sentences.map(async (sentence) => {
            const sentenceEmbedding =
              await this.embeddingProvider.embed(sentence);
            return this.cosineSimilarity(queryEmbedding, sentenceEmbedding);
          })
        );

        // 只保留高于阈值的句子
        const relevantSentences = sentences.filter(
          (_, index) => sentenceScores[index] >= this.options.threshold
        );

        return {
          ...result,
          content: relevantSentences.join(" "),
          metadata: {
            ...result.metadata,
            originalSentenceCount: sentences.length,
            filteredSentenceCount: relevantSentences.length,
          },
        };
      })
    );

    // 过滤掉内容为空的结果
    return filtered.filter((r) => r.content.trim().length > 0);
  }

  private splitSentences(text: string): string[] {
    return text
      .split(/(?<=[。！？.!?])\s*/)
      .filter((s) => s.trim().length > 0);
  }

  private cosineSimilarity(a: number[], b: number[]): number {
    const dotProduct = a.reduce((sum, val, i) => sum + val * b[i], 0);
    const normA = Math.sqrt(a.reduce((sum, val) => sum + val * val, 0));
    const normB = Math.sqrt(b.reduce((sum, val) => sum + val * val, 0));
    return dotProduct / (normA * normB);
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `threshold` | `number` | `0.5` | 句子相关性阈值 |

#### 使用示例

```typescript
const selectiveCtx = new SelectiveContext(embeddingProvider, {
  threshold: 0.6,
});

const results = await vectorSearch.retrieve(query, { topK: 5 });
const filtered = await selectiveCtx.process(results, query);

// 原始 chunk: "React 是 Facebook 开发的 UI 库。Vue 由尤雨溪创建。
//   React 使用虚拟 DOM 提升性能。React 适合大型应用。"
// query: "React 性能优化"
// 过滤后: "React 是 Facebook 开发的 UI 库。React 使用虚拟 DOM 提升性能。"
// 去掉了与 query 无关的 Vue 相关内容
```

### 5. ContextCompressor（上下文压缩）

#### 概念说明

使用轻量级 LLM 对检索到的内容进行压缩，去掉与 query 不相关的部分，保留核心信息。与 SelectiveContext 不同，ContextCompressor 不是简单过滤句子，而是理解内容后进行智能摘要和压缩。

#### 解决的问题

- 检索到的内容可能很长，超出 LLM 上下文窗口限制
- 大量不相关内容会浪费 token、增加成本
- 压缩后的内容更聚焦，有助于提升生成质量

#### TypeScript 类定义

```typescript
interface ContextCompressorOptions {
  /** 压缩后的目标 token 数量 */
  targetTokens?: number;
  /** 压缩提示词模板 */
  compressPrompt?: string;
}

class ContextCompressor {
  private llmProvider: LLMProvider;
  private options: Required<ContextCompressorOptions>;

  constructor(llmProvider: LLMProvider, options?: ContextCompressorOptions) {
    this.llmProvider = llmProvider;
    this.options = {
      targetTokens: options?.targetTokens ?? 500,
      compressPrompt:
        options?.compressPrompt ??
        `请压缩以下文本，只保留与用户问题相关的核心信息。
要求：
1. 保留关键事实和数据
2. 去除无关的背景描述
3. 控制在 {targetTokens} 个 token 以内
4. 保持信息完整性，不要遗漏要点`,
    };
  }

  /**
   * 压缩检索结果
   * @param results - 检索结果
   * @param query - 用户查询
   * @returns 压缩后的结果
   */
  async process(
    results: SearchResult[],
    query: string
  ): Promise<SearchResult[]> {
    const compressed = await Promise.all(
      results.map(async (result) => {
        const prompt = this.options.compressPrompt.replace(
          "{targetTokens}",
          String(this.options.targetTokens)
        );

        const response = await this.llmProvider.chat(
          [
            { role: "system", content: prompt },
            {
              role: "user",
              content: `用户问题：${query}\n\n原始文本：${result.content}`,
            },
          ],
          {
            model: "gpt-4o-mini", // 使用轻量模型降低成本
            maxTokens: this.options.targetTokens,
          }
        );

        return {
          ...result,
          content: response.content.trim(),
          metadata: {
            ...result.metadata,
            originalLength: result.content.length,
            compressedLength: response.content.trim().length,
          },
        };
      })
    );

    return compressed;
  }
}
```

#### 关键参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `targetTokens` | `number` | `500` | 压缩后的目标 token 数量 |
| `compressPrompt` | `string` | 内置默认模板 | 压缩提示词模板 |

#### 使用示例

```typescript
// 使用轻量模型进行压缩，降低成本
const compressor = new ContextCompressor(llmProvider, {
  targetTokens: 300,
});

const results = await vectorSearch.retrieve(query, { topK: 5 });
const compressed = await compressor.process(results, query);

// 原始内容 2000 tokens → 压缩后 300 tokens
// 保留了与 query 相关的核心信息，去掉了无关内容
for (const result of compressed) {
  console.log(
    `压缩率: ${
      ((1 - result.metadata["compressedLength"] / result.metadata["originalLength"]) * 100).toFixed(1)
    }%`
  );
}
```

## 模块组合使用

检索模块的各个组件可以灵活组合，构建适合不同场景的检索管道：

```typescript
/**
 * 完整的检索管道示例
 */
async function buildRetrievalPipeline(): Promise<SearchResult[]> {
  const query = "如何优化 React 应用的性能";

  // 1. 查询变换
  const rewriter = new QueryRewriter(llmProvider);
  const rewrittenQuery = await rewriter.transform(query);

  // 2. 多路检索
  const vectorResults = await vectorSearch.retrieve(rewrittenQuery, {
    topK: 20,
  });
  const keywordResults = await keywordSearch.retrieve(rewrittenQuery, {
    topK: 20,
  });

  // 3. RRF 融合
  const rrf = new RRF();
  const fused = rrf.fuse([vectorResults, keywordResults]);

  // 4. 阈值过滤
  const filter = new ThresholdFilter({ threshold: 0.5 });
  const filtered = await filter.process(fused, query);

  // 5. Reranker 重排序
  const reranker = new Reranker(rerankerProvider, { topK: 10 });
  const reranked = await reranker.process(filtered, query);

  // 6. 上下文增强
  const enricher = new ContextEnricher(chunkStore, { window: 1 });
  const enriched = await enricher.process(reranked, query);

  return enriched;
}
```
